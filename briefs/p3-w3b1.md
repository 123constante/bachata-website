## What to build
A read-only History screen for one event at `/account/p3/events/:id/history`, linked from the P3 event page (a "History" row, appended in `EventPage.tsx`). It shows what changed, when and by whom, in plain words. NO writes, NO Undo (History Undo beyond `series.upsert` waits for admin item A3 R2; do not draw an Undo button).

## Data source (proven read-only on prod, 2026-10-28; re-prove before you build)
`public.organiser_series_history_v1(p_series_id uuid, p_limit integer DEFAULT 50, p_before timestamptz DEFAULT NULL) returns jsonb`, STABLE SECURITY DEFINER, readable by the series team (`_organiser_series_reader_v1`). Limit is clamped 1..100. Shape:
`{ series_id, items: [{ at, kind, label, who, date, fields: [string] }], has_more: boolean, next_before: timestamptz|null }`
- `who` is one of `'you'`, `'a co-host'`, `'the Bachata team'`. `label` is already plain words (e.g. "Created the event"). `date` is a `YYYY-MM-DD` or null (date-level commands). `fields` is a list of plain field labels, possibly empty.
- Paging: pass `p_before = next_before` while `has_more`.
- Source rows: `event_audit_p5` outcome `success`, target series or one of its occurrences.
- Before building, read the live body with `pg_get_functiondef` (read-only SELECT on `stsdtacfauprzrdebmzg`) and state which tables it reads and who writes them. Do NOT call the RPC with a series you do not own from a write path; it is a read, but still use the walk test user's own seeded events (ids in `~/.claude/walk-manifest.json`, or `docs/walk-seed/README.md`).

## Prod shapes (counts only, 2026-10-28)
1,219 series have history rows: 562 with 1 row, 603 with 2-10, 52 with 11-50, 2 with over 50 (max 104). So: one-row (just "Created the event"), a short list, a list that needs a second page, and an empty list (a series with no audit row at all: the RPC returns `items: []`, `has_more: false`, `next_before: null`). The Website must handle all four and an RPC error.

## Rules
- One model, one label list: reuse `p3/model`, the `L` label list in `labels.ts`, the shared sheet/shell components and P3 theme tokens. Append only in shared files (`labels.ts`, `P3Routes.tsx`, `paths.ts`, `p3.css`, `wsFixtures.ts`); website-c2 is rebasing #1079 and #1080 over the same files.
- A reader, not a writer: use React Query and an RPC wrapper in `p3/data/history.ts`, with a parser that rejects a malformed row without crashing the list (unknown `who` shows "someone", missing `label` is dropped and counted in dev).
- Group rows by day (`at` in Europe/London), newest first. Show "You", "A co-host", "The Bachata team". Show `date` as "for Friday 6 March" using full weekday names. Show `fields` as "Changed: Name, Price".
- Empty state says what the person CAN do: "Nothing has changed yet. When you edit this event, it shows here." with a link back to the event.
- Error state has "Try again". Load-more button at the bottom while `has_more` (not infinite scroll).
- A refused or not-allowed read (not on this event's team) shows the same copy the other P3 screens use for a refusal.
