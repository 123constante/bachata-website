## What to build
1. **Make the sweep light enough to succeed**: page the PR list in small batches (e.g. 10-20 PRs per query, cursor paging) and/or fetch the rollup per PR in a second step; pick the batch size from your measurement and state the numbers (PRs open, query time before / after, nodes per query).
2. **Retry transient failures**: 502 / 503 / 504 and network errors retry with a bounded backoff (e.g. 3 attempts, 2 s / 5 s / 10 s, total well under the job's `timeout-minutes: 6`). A 4xx (auth, bad query) and a GraphQL `errors` body must NOT retry and must still exit 2. A real conflict or an empty board still exits 1, exactly as today (H1 and H2 untouched).
3. **An outage must not red main by itself, but must not be hidden**: if, after the retries, GitHub is still unreachable, keep exit code 2 for "could not run" only if the workflow already treats it as a warning; read the workflow and the exit-code table first. The owner's words: "make the sweep lighter / retry on 504 so a real conflict still fails but an outage does not red main". Decide the least-surprising way inside the script (for example print a clear `GITHUB-OUTAGE` line and exit with the code the workflow already maps to neutral), and put in the handover the exact workflow edit if one is needed.
