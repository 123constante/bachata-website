# Mockup B &mdash; Photo-led (Airbnb-host warmth)

**Idea.** Your events are photos first. Home is a swipeable row of big cover cards (name + next date over the photo) and one warm "This month: 893 people looked at your events" card.
The event page opens on a full-width cover with "Change photo" right on it, then friendly cards (next date, dates, line-up, numbers, co-organisers).
A missing photo is the loudest thing on screen ("Add a photo &mdash; events with a photo get more looks"). Creating a course is a short StepFrame: one question per screen with a progress bar.

**Screens** (open `B.html`; desktop shows a shortcut list beside the phone; `#id` in the URL also opens one): 1 First day "We found your 6 events" (no claim step) &middot; 2 Home &middot; 3 Event page, Sensual Fridays (weekly social) &middot; 4 Cover photo (+ past photos, + "too big" error) &middot; 5 Dates (no end date, Show 8 more, a cancelled date, year shown past 2026) &middot; 6 Cancel or move ONE date (+ Undo toast) &middot; 7 Line-up search of real profiles (+ "add their name instead") &middot; 8 Co-organisers, all equal, + Invite &middot; 9 See what dancers see &middot; 10 Stats (today / this week / this month, per event) &middot; 11 Add a course (7 questions + done) &middot; 12 EMPTY: Ana, one event, no photo &middot; 13 ERROR: line-up search failed. Also Details, Pause, "Not your event?" as short screens. Featured listing = one quiet dashed line on Home.

**Gaps answered:** G20 (year shown when not this year), G21/G34 (every target &ge; 44px, measured), G22 (one primary per screen, quiet buttons below), G28/G32 (disabled Next says why: "Pick one to carry on"; no reason text inside a faded control), G29/G30 (every empty/error state has a next step), G31 (accent as text uses `--gold-fg`, never `--gold`), G48 (course create switched on), G49 (stats screen shape: looked + saved), G53 (cancel a single date in plain words), G54 (no claim/approve on day one), G55 (line-up search + free-text name), G56 (invite by phone or email, not by page), W3 (one "Ticket link" row).
**Benchmark patterns:** #1 empty state = reason + button with the same words ("Add a photo"); #4 stats as one line with three ranges; #5 Pause as its own state; #6 a "what's next" first line ("Sensual Fridays is on tonight"); #7 courses in minutes. Anti-patterns avoided: no ticketing words, undo instead of irreversible cancel, no roles to explain, stats not hidden behind "More".

**Trade-offs vs A (calm) and C (today):** + Most emotionally appealing; makes photos (and so looks) improve fastest; matches the owner's Airbnb taste most literally. &minus; Photos cost phone data and screen height: on Home the 6th event is a swipe away (the list below repeats them all, so nothing is hidden). &minus; Relies on organisers having decent photos; events without one look visibly weaker (that is the intended nudge, but it can feel like nagging &mdash; the prompt appears once per event, never as a pop-up). &minus; Text over photos needs a scrim; contrast there depends on the photo. C is better at "what do I do tonight"; A is quieter for organisers with many events.

**New primitives:** `CoverCard` (photo + scrim + name/date), `HeroCover` with `ChangePhotoButton`, `PhotoPrompt` (dashed "add a photo" card), `MonthCard` (big number + one sentence), `StepFrame` (progress bar, one question, Next that names why it is disabled), `ChoiceList` (big pressable options, `aria-pressed`), `ActionRow`/`Row` (64px row with chevron), `QuietButton`, `InlineError` (kind, says next step), `UndoToast` (6s). New tokens: light-mode set (Ember has none yet: `--bg #faf6f2`, `--card #fff`, `--fg #22140c`, `--mut #6a5a4e`, `--gold-fg #b2400f`, `--danger #b3261e`), plus `--gold-soft`, `--scrim`, `--photo-ink`, `--shadow` in both modes. Dark = ember.css values unchanged.

**Self-checks (measured with Playwright, Chromium, 390x844, light AND dark, all 19 screens):**
- Text contrast &ge; 4.5:1 on every solid surface: 0 failures. Text on avatar gradients measured by hand: 6.3&ndash;13.1:1 (the script cannot read gradients).
- Tap targets &ge; 44x44 for every button, input and link: 0 failures (big cover cards excluded, they are 300x360).
- No sideways scroll at 390: page and every scroll area, 0 overflow (the cover row scrolls sideways on purpose, inside its own strip).
- Click walk: course with an empty name shows "Give it a name&hellip;"; Monday course offers Mondays, 5 weeks ends Mon 23 November; done returns Home with a toast; cancel one date returns to the event with Undo; Back from the event lands on Home. No page errors (only the blocked font request in the test).
- No "series / occurrence / lifecycle / P5" anywhere in the copy (grep, 0 hits). HTML entities used for punctuation.
