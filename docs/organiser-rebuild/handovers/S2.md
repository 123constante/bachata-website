## Deviations from the brief (read these)

1. **Commands do NOT go through `useRunCommands(seriesId)` with the series version.** Live prod `pg_proc` (2026-10-16, read-only):
   - `series_command_p5` raises `invalid_payload` for any kind not starting `series.`.
   - `apply_aggregate_write_p5` checks an occurrence command's `expected_version` against `event_occurrence_p5.version` of the TARGET occurrence.
   
   The brief's literal route would refuse every write. So the flow sends through the existing `useOwnerCommand(seriesId)`: `occurrence_command_p5`, `target_id` = the date, `expected_version` = the date's own version (from `event_view_p5`), plus an idempotency key. The tests pin this.
   
   **Ask:** amend 4.3 #6 / the S3 brief the same way (S3's cancel is also an `occurrence.*` command).
2. **`dates/DateSheet.tsx`, `DatePreview.tsx`, `dates/index.tsx` are NOT deleted.** The brief says to delete them "once nothing imports them", but they are the per-date line-up editor:
   - plan 4.2 lists it as must-keep;
   - `organiser-date.spec.ts` and `organiser-layout.spec.ts` test it.
   
   It now lives on `/change/:s/:o/lineup`. `events/EditorRows.tsx` (S5's file, 2 lines) and its two unit tests now link there, so the event's date rows open the line-up exactly as on main. **S5:** link the line-up from C37 Details via `ORG_PATHS.dateLineup`. `home/index.tsx` (S1) still uses the deprecated `ORG_PATHS.date`, which now lands on C4; S1 rewrites Home anyway.
3. **C5's "current time" is the date's own start** (`materialised_start_utc`, local-as-Z, the field `set_time` writes), not `event_view_p5`'s session-derived start. Found on the browser walk: the list said 19:00 and the time screen said 20:00 for the same date. A test pins it; it was RED on the old code and is GREEN now.
