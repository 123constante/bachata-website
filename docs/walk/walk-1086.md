## Findings

- **Nothing outside the viewport.** Every sheet (bottom 844), confirm button (bottom 830), toast (724..763) and Back link (370..414) is fully on screen. scrollY is 0 whenever a sheet is open or a refusal shows, so the earlier "scrolled away from Back" bug does not reproduce.
- **No sideways scroll** on any of the 14 screens (scrollWidth 390).
- **No tap target under 44px in the ambassador UI** (rows, Approve/Reject, sheet buttons, Back link, retry/sign-in). The only sub-44 items are site chrome shared with every page: the 14px-high footer links (shots 2 and 14), the 1x1 skip link, the header "Home" and breadcrumb links (17px high). Not this PR; noted for the owner.
- **Console errors:** none on any screen except the expected network echo of the stubbed refusals: 400 + "Mutation error self_approval_not_allowed" (9), 401 + "Query error JWT expired" (11), 500 + "Query error boom" (12). They are `console.error` lines the app logs on purpose, not page errors.
- **Observation (not a defect in this PR):** the stub user has no dancer profile, so the global "Your dancer profile is missing" banner (about 190px) sits above the queue on every screen (see 01-list.png for the effect on the list). A real ambassador without a dancer profile would see it too. Worth a look by the owner, outside this PR.
- **Observation:** the toast (8) overlaps the 7th and 8th rows of the list for 3.5s; transient and fixed, acceptable, but it does cover content on a phone.
- 8's "scrolled position": scrollY 0. Approve was pressed from the review (itself at scrollY 0), the app returned to the list at the top, toast at y 724..763 (above the 844 fold, 81px from the bottom).
- 100-row page (14): scrollY 6056 of 6900, bottom of the page is the footer. The "more waiting" note position was not separately measured; look at the PNG.

## Verified

- All 13 requested screens plus the 100-row variant captured, measured, and each PNG saved; shots 2, 8, 9 viewed by eye; others read from measurements.
- Spec ran green twice (6 tests) against the unmodified PR source at 59cb27b.

## Not verified

- Real devices, real iOS Safari / Android keyboard behaviour (reject textbox with the on-screen keyboard open was not simulated).
- Real production data shapes (stubs only; no Supabase read was made in this walk).
- Contrast and screen-reader behaviour; reduced-motion; safe-area insets (`env(safe-area-inset-bottom)` is 0 in desktop Chromium).
- First run showed "Invalid hook call" errors on the first page load; they came from Vite's cold dependency re-optimisation in the dev server (different dep hashes in the stack) and did not recur on the second run. Treated as a dev-server artefact, not verified against a production build.
