# Journey grid: entry x state x action -> END

This grid is derived from [`ACCOUNT-MODEL.md`](ACCOUNT-MODEL.md). It **supersedes the rows of**
`docs/review-packs/public-journeys/MATRIX.md`; each row keeps the matching MATRIX id in its `matrix` field, so
nothing is lost. The source is [`journey-grid.json`](journey-grid.json). The tables below are generated from it
by `python3 docs/account-system/build_grid.py`, so edit the JSON, not the tables.

## How a row is built

- **Entry** is one public way in: OL, DL, SI, TI, CL, DI, DP, AC or XD (the group headings below).
- **State** is a named state from ACCOUNT-MODEL section 3 (`S-*`), plus the qualifier the row needs.
- **Action** is what the person does.
- **END** is the screen and state they end in. It is taken from the model's transition (`transition` field,
  `T-*` ids). An END that waits on an owner answer names the decision (`D*` in [`DECISIONS.md`](DECISIONS.md))
  and states the recommended default.
- **Covered by** keys:
  - `J:<id>`: a row of `tests/journeys/publicEntryJourneys.ts`. It is walked by the routing model AND by the
    production build at 390x844.
  - `R:<title>`: a test in `tests/e2e-build/*.build.spec.ts`.
  - `E:<spec>`: a gated spec in `tests/e2e`.
  - `U:<file>`: a unit test file.
  - `OTP:<spec>`: a spec that reads the real e-mailed code from a test project (owner decision O7).
- **Gate**:
  - `required` means a real account can hit the row (prod has people in that state, or the state is "new
    visitor"). Owner decision O8 says such a row needs at least one test **and** one walk (J, R, E or OTP)
    before merge.
  - `optional` means 0 prod accounts are in that state. Such a row needs a test only.
- **Pruned combinations** are listed in MATRIX.md "Pruned combinations". They still hold, because the
  reasons are about code paths that are shared, and that has not changed. One exception: MATRIX pruned "erase
  grace" because the Website has no grace path. The admin repo does have one, and it conflicts with O4. It is
  handled in PLAN PR-2, not as a grid row.

## The proposed CI check (not built; PLAN PR-1 builds it)

`scripts/check-journey-grid.mjs`, added to the `npm run lint` chain and to `architecture-guard.yml`. It follows
the six rules of `check-script-conventions.mjs` (read `docs/ci-guard-notes.md` first).

1. It loads `docs/account-system/journey-grid.json`. It fails on a duplicate `id`, an unknown `entry` or
   `kind`, or a `state` that does not start with an `S-` id defined in ACCOUNT-MODEL.md (it reads the
   "Named states" table).
2. It resolves every `covered_by` entry. Each kind is checked a different way:
   - **J**: the id must exist as `id: '<ref>'` in `tests/journeys/publicEntryJourneys.ts`.
   - **R**: the exact title must appear in a `tests/e2e-build/*.build.spec.ts`. Template titles are expanded
     from their `for` tables.
   - **E**: the spec must be listed in `package.json` `test:e2e`.
   - **U**: the file must exist and contain at least one `it(` or `test(`.
   - **OTP**: the spec must exist under `tests/e2e-otp/`.

   A dangling reference fails the check. This is the step that stops coverage claims from rotting.
3. Every `required` row must have one test of any kind and one walk (J, R, E or OTP). Every `optional` row
   must have one test. A row whose `built` is `NOT BUILT` is exempt until its PR flips it to `BUILT`. The PR
   that builds the behaviour must add the coverage in the same diff.
4. **Ratchet, not big-bang.** The first commit records today's gaps in `scripts/journey-grid-baseline.json`.
   The check fails only on a *new* gap, or on a gap closed without removing it from the baseline. The
   baseline may only shrink. Self-test: a fixture grid with one dangling `J` ref must exit 1, and a fixture
   with full coverage must exit 0 (non-vacuity).
5. **Reverse direction.** Every `J` row in `publicEntryJourneys.ts` must be referenced by at least one grid
   row, so no test exists outside the model.

The check cannot verify that a walk asserts the stated END. That stays a review duty. The PR template's
"Verified on real data" block names the grid rows that were walked.
