## Design you must implement

### PART 1 -- required jobs (A17, A17b)  [do first]
1. `.github/automation/required-jobs.json`: `{ "version": 1, "pr_head": [..], "conditional": [{ "name": "...", "when": "<documented condition>" }], "post_merge_audits": ["Owner approval audit"] }`. `pr_head` = ONLY check-run names that ALWAYS exist at a PR head (a skipped conclusion is fine). Seed from the 7 ruleset contexts (fact 1) plus any other `pull_request`-triggered job `docs/ci-guard-notes.md#workflow-inventory` says must pass; for every job you considered, one line in the handover: included / excluded + why. A job behind a workflow-level path or label filter goes in `conditional`: checked only when present (present and not OK = refuse), never demanded.
2. `scripts/lib/required-jobs.mjs` (pure, Node built-ins): `parseRequiredJobs(text)` (fail closed on bad JSON/shape), `checkRequiredJobs({ required, checkRuns, headSha })` -> `{ ok, missing: [], notGreen: [], reason }`. Only runs whose `head_sha` equals `headSha` count; the LATEST run per name (highest id) decides; OK = `success` | `skipped` | `neutral` (the lane's existing OK set; do not tighten what main already accepts); missing / `in_progress` / `queued` / `cancelled` / `failure` / `timed_out` / `action_required` / `stale` = refuse with the reason text `required job missing: <name>` (absent) or `required job not green: <name>=<state>`. An empty or unreadable check-run list = refuse.
3. Wire into the merge lane: `mergeVerdict(facts)` takes `facts.requiredJobs` (the checker result) and refuses on it (an absent field = refuse, fail closed); `scripts/autopilot-step.mjs` `mergePr` (THE one merge call site) RE-READS `GET /repos/{repo}/commits/{pinned head}/check-runs` (paginated, `per_page=100`) immediately before the merge PUT, evaluates the file read from the MAIN checkout (never the PR), and does not merge on a refusal. Place this re-read AFTER slice 1's pause re-read and immediately before the PUT.
