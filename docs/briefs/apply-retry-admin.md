## Design you must implement

### PART 1 -- pure foundations (tests first)
1. `scripts/lib/apply-outcome.mjs` (pure): `classifyApplyError(err)` -> `{ kind: 'server-error' | 'pre-write-transport' | 'ambiguous-transport' | 'timeout', code, detail }`. The ALLOW-LIST of PRE-WRITE transport errors is deliberately minimal and exported as one constant `PRE_WRITE_TRANSPORT`: DNS failure (`ENOTFOUND`, `EAI_AGAIN`), connection refused (`ECONNREFUSED`), TLS/handshake failure before the request is sent (Node `ERR_SSL_*`, `EPROTO`, the `fetch failed` cause codes that mean the TLS handshake failed; this is the contract's "curl 35" class) and HTTP 429 from the Management API (rejected before processing). EVERYTHING else is NOT on the list: any timeout (`ETIMEDOUT`, `UND_ERR_*TIMEOUT`, an abort from `timeoutMs`) = `timeout`; `ECONNRESET`, `EPIPE`, `UND_ERR_SOCKET`, a body that is not JSON, HTTP 5xx (a 502/504 can arrive AFTER the query ran) = `ambiguous-transport`; an HTTP 4xx other than 429 or any error carrying a Postgres `code`/message from the server = `server-error` (the server evaluated the transaction and rolled it back). A table test covers every code named here plus an unknown code (= `ambiguous-transport`).
2. `scripts/lib/schema-fingerprint.mjs`: `fingerprintObjects(objects)` -> an ordered list of read-only catalogue SELECTs (one batch) for the PARSED OBJECT LIST of fact 8, and `snapshotFromRows(rows)` -> a canonical object `{ [kind:schema.name]: { exists, hash } }`. Per kind, a deterministic hash over what the migration can change: table = columns (name, type, not-null, default), constraints, indexes, `relacl`, RLS flag, policies, comment; function = `md5(pg_get_functiondef)` + `proacl` + comment; index = `pg_get_indexdef`; view = `pg_get_viewdef`; trigger, policy, type, extension, schema, role as the parsed kind requires (a kind you cannot fingerprint = the migration is NOT fingerprintable: no retry). `compareSnapshots(a, b)` -> `'same' | 'different'`; `matchesPostState` is NOT needed. Reads go through the same transport the applier uses (`mgmtQuery`), are SELECT-only, each with a short timeout (30 s). A parse failure (`parseObjects` returned `ok: false`), an empty object list for a non-empty file, an unfingerprintable kind or a read error = `{ ok: false, reason }` and the caller stops (never "treat as unchanged").
3. `isSingleTransaction(files)` (pure, in `apply-outcome.mjs`): true only when the AST of every file has NO transaction-control statement (`BEGIN`, `COMMIT`, `ROLLBACK`, `SAVEPOINT`), no `CONCURRENTLY` index, no statement that cannot run inside a transaction block (`CREATE DATABASE`, `VACUUM`, `ALTER SYSTEM`, ...), parsed with the classifier's parser, never regexes; a parse failure = false.
4. `decideAfterFailure({ errKind, ledgerRowPresent, preSnapshot, postSnapshot, singleTx, sameHash, attemptsUsed, mode })` -> `{ action: 'retry' | 'stop', reason, alert: 'none' | 'possible-post-write' | 'half-applied' | 'stop' }`. RETRY only when ALL hold (contract case (e)): `errKind === 'pre-write-transport'`; `ledgerRowPresent === false` (a SUCCESSFUL, read ledger answer; an unreadable ledger is NOT false); `compareSnapshots(pre, post) === 'same'`; `singleTx`; `sameHash` (sha256 of the file bytes now equals the sha256 recorded before attempt 1); `attemptsUsed === 0` (ONE retry in total, ever, per file per run); mode is `act`. Table of everything else: ledger row present after ANY failure = `stop`, alert `possible-post-write` (the migration may have committed: say what the read showed, never "rolled back"); ledger absent but snapshots differ = `stop`, alert `half-applied` (case (p)); `timeout` = `stop`, alert `stop` naming the timeout and the ledger read; `ambiguous-transport` = `stop`, and when the ledger read shows the row present the alert is `possible-post-write`, when absent and snapshots same the alert is `stop` ("no change detected; not retried because the error class is ambiguous"); `server-error` = `stop` (a real failure, today's behaviour, and now the "rolled back, nothing changed" claim is verified by the same two reads); any read failure = `stop`.

### PART 2 -- wire the retry and the truthful message
1. `scripts/apply-migration.mjs`: in the final `catch` of `main()` use `classifyApplyError(err)`: for `server-error` keep the existing text; for every other kind print instead `apply-migration: FAILED -- OUTCOME UNKNOWN (<kind> <code>): the transaction may or may not have committed; the caller must read the ledger before anything else.` and a final machine-readable line `APPLY-OUTCOME: <kind> <code>`; exit code stays 1. Add an OPTIONAL request timeout: `APPLY_REQUEST_TIMEOUT_MS` env (default unset = today's behaviour; the workflow sets 900000) passed to `mgmtQuery` as `timeoutMs` (AbortController); on abort the error code is `APPLY_TIMEOUT` and classifies as `timeout`. `mgmtQuery`'s signature gains the optional options object and is otherwise byte-identical.
