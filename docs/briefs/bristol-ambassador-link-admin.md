## What to build
1. Tables with RLS ON and explicit GRANT/REVOKE for anon, authenticated and service_role (no auto-grants since 2026-10-30). `ambassador_invite_links(id, ambassador_user_id, city_id, code unique, is_active default true, created_at)`, one live row per ambassador. `ambassador_link_joins(id, link_id, user_id unique, joined_at, city_set boolean default false)`. Direct table access: none for anon; the ambassador may read only their own link.
2. RPCs, SECURITY DEFINER, `SET search_path`, ACL reviewed (anon only on the landing read): `get_ambassador_link_public_v1(p_code)` returns first name, city name and slug, active flag, nothing else (no email, no user id); inactive or unknown code returns a neutral "not_found" shape. `record_ambassador_link_join_v1(p_code)` for a signed-in caller, idempotent, ignores a second code. `get_ambassador_link_tracker_v1()` returns counts and first names for the caller's own link (owner/admin sees any). `set_ambassador_link_active_v1(p_link_id, p_active)` owner/admin or the link's own ambassador. `is_city_ambassador_public_v1(p_user_id)` returns a boolean only.
3. The link row is created only through the existing member-role path: when an `entity_members` row with member_role 'ambassador' is added, create the link (trigger or inside the add command; pick the smaller diff and say which in the PR).
4. Tests table-driven: every RPC x caller (anon, stranger, joiner, ambassador, owner) x link state (active, off, unknown code) x city (active, inactive); rejection shapes are stable codes; a joiner counted once.
4b. Replay proof (`check:replay`), CI jobs run in the sandbox, per-job table in the PR body. Migration applied by the lead after independent review; you never apply.
