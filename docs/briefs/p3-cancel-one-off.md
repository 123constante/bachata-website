## Why (owner decision 11, prototype v7)
On a one-off, the cancel control means END THE EVENT, with a reason. Admin AD4 is live on prod (#963, ledger 20261204180000/190000): `series.cancel_one_off` cancels the one date through the date-cancel writer, the series stays `live`, the public calendar drops the row, the event page still loads and shows the date "Cancelled" with the reason. Nothing on Website main calls it.

## Where it belongs in P3 (from C2/C3 mockups + CONTRACT section 2)
- C3 "Manage/status" sheet has `data-sheet="endit"` ("This has finished (end it)" -> `series.end_run`). For a one-off that has NOT run, that row is disabled with "It hasn't run yet, so it can't end. Take it off the calendar instead." That dead end is the gap. Put the new row next to it: **"Cancel the event"** (one-off, live, date still ahead) with the reason picker, replacing the disabled reason.
- C3 date sheet for a one-off shows "Cancel this date" (`data-act=cancel`, `cancelnext` sheet, `reasonPick`). On a one-off that is the same act, so it must open THE SAME sheet and send THE SAME command: one control, one mapping, label `L.cancelEvent` ("Cancel the event"), never two copies. Recurring/course/custom keep "Cancel this date" -> `occurrence.cancel` (unchanged).
- `endit` stays for events that ran (`series.end_run`). Cancel = never ran / will not run; End = it ran.
