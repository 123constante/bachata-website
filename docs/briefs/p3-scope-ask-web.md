- "Keeps hand-edited dates" is already how the data behaves (an all-dates write changes the series default and creates or changes no override row), but the owner cannot see it or choose "just this date". -- extends: src/modules/organiser/p3/model (new file)
- The scoped RPC covers FOUR fields only: cover image (`cover_image_url`), gallery (`gallery`), venue (`venue_id` + `city_id` together), prices (`passes`). Description, music styles, ticket link, Instagram, videos, name, chat link and payment methods are NOT in it; they stay all-dates saves exactly as today. -- extends: src/modules/organiser/p3/data/details.ts, prices.ts (read only)
- Prod shape (counts only, 2026-11-04): 762 series; 1,978 future scheduled dates; 52 series have more than one future date; 385 override rows (cover 232, gallery 50, venue 191, passes 0); 10 series have a future date with an override row. ## What to build (tests first, red; say so)
1. Model `scopeAsk.ts`. `scopedFieldsChanged(draft changes) -> ScopeField[]` with `ScopeField = 'cover_image_url' | 'gallery' | 'venue' | 'passes'` (venue sends `venue_id` + `city_id` together, as the RPC requires). `needsScopeAsk({ changedScoped, unscopedChanged, futureDates })`: true only when at least one scoped field changed AND the event has 2 or more future scheduled dates (the preview's `totals.dates`, not the workspace's date list, because past and cancelled dates are not counted by the RPC). One date, none, or no scoped field changed: no sheet; the save is today's exact `series.upsert`, byte for byte (flag-off and one-date cases change nothing).
2. Data `scopeAsk.ts`. `previewScope(seriesId, fields)` calls `series_scope_change_preview_v1` and returns the typed counts: `totals.{dates, applied, kept, curated_but_inherits}` and per date `{occurrence_id, occurrence_date, kept_fields, applied_fields}`. Counts only; the reply holds no names. `sendScoped({ scope, seriesId, occurrenceId?, changes, expectedVersion })` calls `series_scoped_change_p5` with the envelope in `docs/design/scope-ask-api.md` (`idempotency_key` a uuid kept in a ref until the call succeeds or the person taps "Start again", so a dropped-connection retry is the same write; `all_dates` has NO `occurrence_id`; `expected_version` = the series version for all dates, the date's version for one date). Use the same RPC client helper `runSeriesCommand` uses (`src/modules/organiser/shared/runCommands.ts`); no new client. Map its errors through the existing `commandErrorMessage`/`repeatFailure`-style single mapping; reuse the onboarding-gate handling (`isOnboardingRefusal` opens the gate sheet) exactly as `useSaveRun` does. The reply's `applied_dates` / `kept_dates` feed the post-save line.
3. Screen `ScopeSheet.tsx` (a `Sheet`, title "Which dates?"), opened from Save when `needsScopeAsk`. It first calls `previewScope` (loading state; a failed preview shows a "Try again" button and still offers nothing else that could write; never auto-sends). Then two choices, each a 44px-min-height button (explicit px, the root font trap applies):
   - "All N dates" with the preview line: none kept: "Every date changes."; some kept: "N dates change. M keep their own &lt;pictures|place|prices&gt; because you edited them by hand." (the field word comes from `kept_fields`; one mapping `FIELD_WORD`); a date edited by hand but not for this field is NOT kept and takes the change (D14), say nothing about it beyond the count.
   - "Just one date": a short list of the upcoming dates from the preview (full weekday names, e.g. "Friday 7 November", at most 8, then "Pick another date" is NOT built: say "Use the date's own page for later dates" with no link if more than 8; no control that does not exist). Picking one sends `this_date` for that `occurrence_id`.
   - "Just one date" is DISABLED with its reason ("Name, description, music and the other details change every date. Save those first, then change this one.") when any UNSCOPED field also changed in the same draft; the all-dates choice then sends today's exact save (the existing `series.upsert`, unchanged) and no scoped call at all (nothing to ask: the `upsert` already keeps overrides).
   - A "Cancel" returns to the form with the typing kept and nothing sent.
   - Choosing "All N dates" sends the scoped `all_dates` call when ANY scoped field changed and nothing unscoped did; when both changed it sends today's single `series.upsert` (as above) so the save stays one write. Say this in the handover with the table of cases.
4. After a save: toast words. All dates, none kept: the existing "Saved for all dates ..." line, unchanged. Some kept: the existing line plus "M dates kept their own &lt;word&gt;." (built from the reply's `kept_dates`, not from the preview). One date: `savedDate(day)` from `saveWords` ("Saved for Friday 7 November only. ...").
5. Details and Prices wiring: `onSave` builds today's plan; if `needsScopeAsk`, open the sheet instead of running; the sheet's choice runs the scoped call or today's plan through the existing `form.saved` / `form.landed` / `back(words...)` path so Undo, Start again and the kept-draft gate behave as today. An untouched draft still sends nothing.
