4. **Data** `src/modules/door/data.ts`: `door_list_v1` and `door_scan_v1` via `rpcLoose`. Refusal (42501 or the R1 code) -> `not_allowed`; JWT missing -> "You were signed out" card with a sign-in link (`/auth?returnTo=/door/<id>`). Any other failure -> offline path (item 6).
5. **Saved list (IndexedDB)** `src/modules/door/offlineStore.ts`: "Save tonight's list" stores the `door_list_v1` reply per `occurrenceId` with `savedAt` and the signed-in user id; reads are scoped to the same user id (another account on the same phone sees nothing). Every IndexedDB call wrapped in try/catch; when IndexedDB is unavailable the button is disabled with the reason "This browser cannot save the list; scanning still works online". Shows "Saved N names at HH:MM" (London). Re-saving replaces, never merges.
6. **Offline scan + sync queue** `src/modules/door/syncQueue.ts`: when offline (or a scan call fails on the network), resolve the payload against the saved list -> `offline_*` card with the name; an `offline_admitted` marks that row used locally (a second offline scan of the same token -> `offline_used`) and enqueues the raw payload. On `online` (and on mount) replay the queue in order through `door_scan_v1`; a replay answering `already_used` for a code this device admitted offline counts as synced, not as an error; `voided`/`unknown` on replay -> a visible "N scans need a look" list with the names. Counters on screen: saved list size, pending sync, synced. The queue persists across reloads (IndexedDB) and is per user + occurrence.
