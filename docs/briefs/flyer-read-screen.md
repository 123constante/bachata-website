## Goal
Let a signed-in organiser start a new event from a flyer photo: pick a photo, see "Reading your flyer", land on the normal P3 New event form pre-filled, doubtful fields marked "check this", sessions as a tick list, flyer as the cover on save. Nothing is saved until the usual save. Dark behind a new flag `organiserFlyerReader` (off by default, Ritmo Latino first, then every signed-in organiser once the first 20 real flyers pass: 14 of 20 saved unchanged).

## Context (owner clicks 2026-11-07/08; plan ~/.claude/plans/resilient-wishing-crab.md)

There is no "Start blank" text on main: add the flyer entry on the kind step as one extra row/button, "Start from a flyer", beside the existing kinds. Uses `flyerToDraft(read, venues, today)` from slice 2 (`p3/new/flyerToDraft.ts`) and the function `event-flyer-read` from slice 1 (response format in `p3/new/flyerReadShape.ts`). 2. **`useFlyerRead`:** takes a File; runs `checkFlyerFile` (show `FLYER_PROBLEM_COPY` on a problem), `reencodeFlyer` (max edge and size as the function accepts: jpeg/png/webp, 5 MB: downscale and re-encode BEFORE sending so a normal phone photo always fits), posts base64 JSON `{ image, media_type, today }` to the `event-flyer-read` function with the signed-in user's token (never the anon key; see how other organiser code calls edge functions), and returns a discriminated result: `read` (parsed by `parseFlyerRead`), `refused` with the function's reason (`daily_limit` with `resets_at`, `attempts_limit`, `switched_off`, `not_organiser`, `unauthorised`, `bad_image`, `read_failed`), `offline`, or `error`. 3. **`FlyerStart` states, each with a way forward (draw and look at each at 390x844):** choose (explains in one line what it reads: title, dates, time, venue, sessions, price, ticket link; says "nothing is saved until you save"); reading ("Reading your flyer", cancel); read ok (goes to the form); failed or not a flyer ("Couldn't read that one", try another photo or fill it in yourself, the blank form is one tap away); daily limit ("You've used today's 5 flyer reads, back <weekday time>", blank form one tap away); switched off ("Flyer reading is paused for now", blank form); offline; not enough ("Not enough on this flyer to fill the date and venue, here is what we found"). Copy: British English, full weekday names, plain words, no Unicode punctuation pasted into JSX (use `&mdash;`/`&hellip;`/`&rsquo;`).
4. **Hand-off to the form:** `flyerToDraft` result becomes the starting `CreateDraft` (kind from the flyer, never the kind the organiser tapped); store it through the same draft storage the flow already uses (`DRAFT_STORE_KEY`) so Back/refresh behave exactly as today; fields in `doubtful` show a small "check this" mark and clear it when the organiser edits that field; `notes` (weekly, several events, past date, not enough) show as a calm note at the top of the form; `venueSaid` shows as "Flyer says: ..." beside the normal venue picker when no venue matched; `sessionChoices` show as a tick list (only ticked ones are added through `applySessionChoices`); the flyer file is kept in memory and uploaded as the cover ONLY on the normal save, via `uploadFlyer`, and deleted/forgotten if the organiser leaves without saving.
