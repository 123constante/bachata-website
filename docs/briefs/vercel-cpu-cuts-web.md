Always measure with GET (`curl -s -D - -o /dev/null`) and a browser User-Agent, never `-I`.

## Risks to check and report (do not fix beyond scope)
- **Stale card for a year.** The healthy card's `s-maxage=31536000` is keyed on `v=` (cover version) only, and `/api/og/*` is excluded from the `Cache-Tag: html` purge. A title, date or venue edit with an unchanged cover therefore leaves a stale card in Vercel's cache until the next deploy and, once a Cloudflare rule exists, in Cloudflare until its TTL. `ogFactsTag` (the facts hash in the ETag) is only active when `OG_BRANDED_CARD_ENABLED`. Report how `v=` is built (`coverVersionToken` in `app/detailLoader.ts`, `resolveOgCardImage`), whether facts feed it, and recommend a Cloudflare TTL accordingly.
- **Cloudflare ignoring `no-store`.** `docs/ops/vercel-html-caching-2026-10-08.md` measured that Cloudflare cached a `no-store` 404; the unknown-path 404 for humans is therefore already cached 5 minutes there. Confirm whether the same applies to a bot UA (bots bypass), and that slice 3 does not create a conflict between the two layers.
- **HEAD does not fill the Vercel cache**, so any monitor or guard that uses HEAD (`check-og-images.mjs`, the synthetic monitor) both reports MISS and costs a render each time. List any such caller you find.
- **Skew cookie on an edge-cached 404.** Make sure an edge-cached 404 can never carry `Set-Cookie: __vdpl` (Vercel does not store a response with `Set-Cookie`, which would silently void slice 3).
- Anything else in the existing cache design that looks wrong: report it, do not change it.
