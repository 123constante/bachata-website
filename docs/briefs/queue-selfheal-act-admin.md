## Design you must implement

Mode for ALL three actions: read `queue_selfheal_mode` from `.github/automation/arming.json` on MAIN through `scripts/lib/arming.mjs` (never a variable; if the key is missing/unreadable the mode is `log`). `log` = compute and PRINT the decision (`would clear ...`, `would rerun ...`, `would kick ...`) and change nothing; `act` = do it. EVERY write is preceded by the pause read of slice 1 (`readPause`, no caching, re-read immediately before each write) and by `isMoney`-free logic only (these actions touch labels, CI runs and dispatches, never PR content). A pause = write nothing, log `paused: <reason>`, exit 0. The marker comments below are the only comments these actions post, carry NO `@` mention, and are de-duplicated by key.

### PART 1 -- the global rerun counter
`scripts/lib/rerun-counter.mjs` (pure): `rerunMarker({ pr, reason, jobId })` = `<!-- automation-rerun pr=<N> reason=<cancelled|flaky|body> job=<id> -->`; `rerunsUsed(comments, pr, bot = 'kiki-claude-bot')` counts markers authored by the bot on that PR across ALL reasons; `canRerun(comments, pr)` = `rerunsUsed < 1` (section 12: reruns per PR, 1 total across all reasons). The marker is posted BEFORE the rerun request (write-ahead: a crash between marker and rerun costs one rerun that did not happen, never two that did). Unreadable comments = cannot rerun (fail closed).

### PART 2 -- (b) rerun a cancelled check once, then proceed
1. `scripts/lib/migration-queue.mjs`: `decideCheckRuns` keeps every existing result string and state; its `red` results gain `{ name, conclusion, id, detailsUrl }` of the run that caused them (additive fields only; existing tests keep their assertions).
2. `scripts/lib/queue-selfheal-act.mjs` pure `decideCancelledRerun({ red, comments, mode, runInfo })` -> `{ action: 'rerun' | 'stop' | 'log', jobId, reason }`: a rerun only when ALL hold: the red run's `conclusion` is `cancelled`; it is a GitHub Actions job check-run (`detailsUrl` matches `/actions/runs/<run>/job/<job>`; the job id is the rerun target; anything else = `stop`); it was NOT superseded (that case is already "wait" in `decideCheckRuns`); `canRerun(comments, pr)`; mode is `act`. A cancelled run when the counter is used up (the SECOND cancellation, or any earlier rerun on this PR for another reason) = `stop` with the existing `check <name>=cancelled at <sha>` text (the existing `stop()` alert fires once per head via #1226); mode `log` = `log` (prints `would rerun-cancelled <name>`) and the queue continues to its existing red/stop behaviour.
3. `migration-queue.yml` step `Wait for required checks at the new head`: on a red result whose conclusion is `cancelled`, call the TRUSTED copy of the CLI (`$RUNNER_TEMP/qtrust/scripts/queue-selfheal-act.mjs rerun-cancelled`, env only: `GH_TOKEN`, `REPO`, `PR`, `HEAD_SHA`, `JOB_ID`, `JOB_NAME`; never PR-controlled text on a command line) which, in act mode, posts the marker, then `POST /repos/{repo}/actions/jobs/{job_id}/rerun` (only that exact job), prints `rerun-cancelled: <name> job <id> at <sha>`, and the wait loop CONTINUES (the new run supersedes the cancelled one by the existing monotonic-id rule); a second cancellation falls to `stop`. Pause read before the marker and before the rerun call. The rest of the step is unchanged.
4. Interpretation to state in the doc and handover: the contract says "automerge check CANCELLED at a queue-pushed head"; this brief applies it to ANY cancelled check-run at the head the queue pushed (the one the Wait step watches).
5. `scripts/queue-canary.mjs`: scenario for drill A4 (a check is cancelled at the queue head: ONE rerun, then the merge proceeds; two cancellations: stop plus exactly ONE alert and nothing merged) run in act mode, and a `log`-mode scenario (no rerun, today's stop); the fake GitHub learns the job-rerun endpoint. Mutants: the rerun step removed; the counter check removed (a second rerun happens): both must turn the canary red.

### PART 3 -- (a) clear a stale `queue-stopped` label
1. `scripts/lib/queue-selfheal-act.mjs` pure: `stopCause(alertComment)` parses the #1226 alert (marker + `Reason:` line) into `{ head, reason }`; `CAUSE_TABLE` maps EVERY `stop` reason of fact 2 (and every `stop` call site that exists when you start) to a class: `proof: 'checks-green'` (reasons `check <x>=...`, `commit status ...`, `required checks did not finish ...`, `required job missing: ...`: gone when, at the CURRENT head, `decideCheckRuns` is `green`, the combined commit status is not `failure|error|pending`, and `checkRequiredJobs` (foundations) is ok), `proof: 'mergeable'` (`PR is not mergeable`, `the branch conflicts with main`: gone when the PR reads `mergeable === true` and not behind main), `proof: 'approval-at-head'` (`approval is not valid for the current head`, `the merge of main cannot carry the approval`: gone when `decideApproval` (`scripts/lib/pr-approval.mjs`) says approved at the CURRENT head), and `proof: 'never'` for everything that cannot be proven gone from PR facts: every infrastructure/push/checkout failure, `main moved since Assign`, `merge refused`, every POST-MERGE reason (`Apply migrations ended ...`, `Apply migrations did not finish ...`, `prod read-back after Apply ...`: a post-write stop is NEVER cleared), and every reason starting `route:`, `money set:`, `guard-path refused:` (those prefixes come from the foundations and classifier slices: list them in one exported constant `NEVER_CLEAR_PREFIXES`). An UNKNOWN reason (not in the table) = `never`. A completeness test greps the `stop "` call sites in `.github/workflows/migration-queue.yml` and FAILS when one is not mapped (so a later slice that adds a stop must classify it).
2. `decideStaleClear({ labels, alert, pr, current, pause, mode })` -> `{ action: 'clear' | 'keep' | 'log', reason }`: `clear` only when ALL hold: the PR is open and carries `queue-stopped`; the alert exists, is authored by the bot and carries our marker (no alert = the label was set by someone else = `keep`); the pause is NOT set (a stop caused by the pause is never cleared by the queue: with the switch set, `keep`); the cause class is not `never`; its proof holds on FRESH reads at the PR's current head.
