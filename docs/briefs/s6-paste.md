## What to build (390x844 first; reuse tokens, no new colours or fonts; plain warm UK English)
A "Paste a link" option at the top of the Add event flow (for the organiser and the admin; same component): a single box "Paste the event link (Facebook, Eventbrite, your own site)" and a "Read it" button. On success show a DRAFT of what was read (title, date(s), venue/city, ticket link, description) in the existing event form fields, prefilled and clearly marked "Check this before saving", never auto-saved, never auto-published; the organiser edits and saves through the EXISTING save path unchanged. Every failure state is a plain sentence and keeps the person moving: unreadable link / empty result / non-https link / 401 (sign in again) / 429 cap ("You have used today's link reads; add this one by hand or try tomorrow") / network error / timeout: each shows "We could not read that link. You can add the event by hand" with a working "Add by hand" button that opens the normal empty form. Double-tap sends once; an untouched box sends nothing; the button is disabled with a reason while empty or while reading; a loading state with a cancel.
Imported values are untrusted text: render as text only, never as HTML; reject non-https ticket links; never copy past dates (a date in the past is shown blank with "This date has passed, please set the date").
