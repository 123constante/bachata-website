## Answers

**Q1 Byte-identical (mode off, no `l`).** In `makeEtag` (`api.og.card.tsx:47-50`) an empty `layout` appends nothing. If `l` is folded in the same way (a segment only when present, for example `:l=wf1`, never equal to the reserved `:layout=tall`), the l-less etag is unchanged at `:197`, `:220` and `:248`. The query parsing (`:179-187`) ignores unknown params today, so `l` absent changes nothing. `resolveOgCardImage` (`detailLoader.ts:318-337`) builds the live URL as `kind, id, occ?, v`. That stays the same if `l` is set only on the whole-flyer path, but the new read rule must leave `baked ?? live` unchanged for the 305 plain and 96 facts keys when the layout is legacy. That holds per D4(c). `event.tsx:288-306` still declares 1200x630 when there is no whole-flyer data. Places that DO change today's output: (1) the X-OG-Layout header on l-less responses (R3); (2) the D5 and D9(2) 1 h cache if it is applied to l-less URLs (R2); (3) `&layout=tall` and `?ogtest=tall` URLs (R5, test-only). With R2, R3 and R5 applied, every other response is byte-identical.

**Q2 N1 states.** Off after the backfill: the read rule rejects wf keys, the page emits the l-less URL and declares 1200x630, and the pixels are 1200x630. Correct. On, not yet baked: legacy keys are rejected, the page emits l=wf1 with the measured size. Correct only if the measure and the render use the same image at the same moment (R1). Re-bake fails half way: the row goes to error and `get_og_image_v1` filters on `status = 'ready'` (prod body), so the page uses the live URL. Correct, with the R1 caveat. Deploy skew and two deploys at once: the route renders the layout named in the URL, so it is correct, given R8. Allowlist: `ogLayoutFor` is the single owner. Correct. Occurrence with series cover: correct only if the page measures the card resolver's cover (R1). A crawler that cached the l-less URL in mode on: l-less is always legacy 1200x630, correct. Old page HTML cached at the edge after a flip: it points at the old layout's URL, which still renders that layout. Correct. `v=` changes: a new URL, but the route does not check `v`, so the OLD URL can render the new cover (R1). Measure-miss while a baked wf object exists: the baked object is read first (`detailLoader.ts:330`) and its size comes from the key, so a measure is needed only when no accepted object exists; the fallback pair (l-less, 1200x630) is consistent. But the page is cached at the edge (R3c). Remaining wrong-size states: R1 (cover race and resolver drift), R4 (degraded and short-lived), R5 (test URLs).

**Q3 Caches.** These can hold an `l=wf1` URL: the browser (`max-age=86400` if CACHE_OK is used; at most 3600 while not on, per D5); the Vercel edge (`Vercel-CDN-Cache-Control` `s-maxage=31536000`, `:116`, discarded per deploy per the repo doc, not verified); Cloudflare (DYNAMIC today; the planned `OG cards` rule, `docs/ops/vercel-cpu-cuts-2026-11-04.md:80-96`, keys on the whole URL and caps 200s at 1 day); the WhatsApp and Facebook URL-keyed preview caches (days, not purgeable); and the iMessage, Telegram, X and Slack unfurl caches. Each of them is keyed by URL, and since `l` is in the URL, none can serve one layout under the other layout's URL. After a rollback, old wf URLs stay in these caches (the browser for up to 1 day, or 1 h under D5; the edge until the next deploy or a year; Cloudflare up to 1 day; WhatsApp and Facebook for days). That is allowed. The only wrong-size-under-a-URL risk left is R1, and the year-long edge entry makes it the one worth fixing.

**Q4 Read rule.** Prod today: event ready plain 296, event ready facts 96, festival ready plain 9 (= 305 + 96), event error 23 with null image. `HEALTHY_BAKED_KEY_RE` (`scripts/check-og-images.mjs:407`) is `<uuid>-(default|<uuid>)-<16hex>(-<12hex>)?.jpg`, so it accepts exactly both legacy shapes. `BAKED_OBJECT_RE` (`:395`) matches `/og/(event|festival)/<key>`. `app/ogImageHost.test.ts:16-18` uses a bare `<uuid>.jpg` fixture, which matches NEITHER legacy shape of D4(c). B1's read rule would turn those fixtures into live-URL cases, so B1 must update them to real key shapes (they are already on the B1 file list). `get_og_image_v1` (prod body) has no layout or shape filter: it returns any ready row whose `cover_hash` matches. So yes, it returns rows the rule rejects (every legacy row in mode on, every wf row in mode off), and with the rule placed where `baked ?? live` sits the page falls back to the live URL for the right layout. With R9's wording the rule is complete. Note: the error path keeps the old `image_url` (`COALESCE` in `set_og_image_v1`), but `status = 'ready'` hides it.

**Q5 Rollback table.** Off to test, test to off: no rows change, true given R7. Off to allowlist before B3: the named events' legacy keys fail the rule, so they get the live whole-flyer card. True. Allowlist to off before B3: true. Any wf object written meanwhile by the cover trigger or og-render-sweep for allowlisted events is rejected, so the page uses live legacy. After B3, to off and on to off: the rule serves live legacy at once, and re-running the backfill with `--layout legacy` re-points the rows. True. Unstated cost: until the re-backfill, every shared event renders live (CPU, see the CPU-cuts doc). "Caches safe by URL": true except R1.

**Q6 Matrix.** Tallied by script, cell by cell. 8a: 13 rows x 6 = 78, yes 46, coded 32, GAP 0, matching the claim. 8b: 13 x 19 = 247, yes 167 (44 fixture-only), coded 80, GAP 0, matching the claim. F11 is yes at K1, K2, K10 and K13 and R5 elsewhere, as claimed, but K9 and K12 should be yes (R6). P6 K9 and K10 = yes are true: the B1 test asserts the page HTML differs only in og:image* and twitter:image. The fixture-only yeses are true: F8 (prod max 1920 px), F16, F17 and F18 (none seen; the F17 fixture is added by B1). The other codes are true.

**Q7 D10.** No. `l` (and `s` from R1) is a query parameter on the existing `/api/og/card`. The key segment is a string built in `api.og.bake.tsx:212`. `set_og_image_v1` stores `p_image_url` as free text with no shape check (prod body), and `cover_hash` comes from `_og_cover_token(cover URL)`, which does not change. `get_og_image_v1` needs no change because the rule lives in TypeScript. No SQL, no table, no route. Section 10: Vercel `OG_WHOLE_FLYER_MODE` and the GitHub variable are set in the same step with the same value (O1, O2, O3 and the "Never" line), which matches D9. No contradiction.
