## Findings

### A. A version change resets typing without a word (nit, CONFIRMED by reading)
- `SessionSheet.tsx` `baseKey` / `form`. Only a scope switch is announced ("Changing which dates clears what you typed here"). If the stored version changes while the sheet is open (another device saved, or a `reload`-type refusal reloads), `edit.k !== baseKey` and the form snaps back to stored with no message. Failing input: type a new name in Just this date, another tab saves that date, the app refetches on focus: the name reverts and Save reads "Nothing changed yet".
- Better than r1 (the same-version refetch is now safe), and no stored data is lost. A one-line "This session changed while you were editing" would close it. Fix before arc end, low priority.

### B. Performance line-up: the explanation sits above controls it contradicts (nit, PLAUSIBLE)
- `LineupSheet.tsx`: `teamOnly` is shown, but the "Add as" Teacher/DJ toggle and the search remain enabled for a performance session. Saying "Performers and the MC are added by the Bachata Calendar team" and then offering to add a teacher is mixed. I did not trace whether the server accepts a teacher on a performance, so I cannot say whether the add is harmless. Hiding the toggle and search when `addRoleFor(type) === null` is the clean fix.

### C. "Give this session a name." shows before the person has typed anything (nit, CONFIRMED)
- `SessionSheet.tsx` `nameWhy` is true on an empty new form, so the error line is on screen on opening. `23-new-session-name` shows that state. Reads as a scolding, not a prompt; cosmetic. Saving stays correctly disabled.
