## Ranked findings

1. **F1 (CI red, PR body) &mdash; `phone-qa-section` fails.** The PR changes UI paths, so the body needs the three lines under `## Phone QA`: `- Sizes checked:`, `- Walked:`, `- Not verified:`. The body has a prose paragraph instead. Fix: PR description only.
2. **F2 (CI red, unrelated) &mdash; `contract-check` fails** at `check-occurrence-delete-booking-safety`: `check_occurrence_delete_booking_safety_v1 not found (PGRST202)` on prod. This PR touches no SQL and no scripts; the missing admin RPC is a main/prod matter. Needs owner: confirm it is red on main too, or land the admin RPC. Not this PR's defect, but the gate is red.
3. **F3 (medium) &mdash; refused caller keeps enabled Check in buttons** (`DoorScreen.tsx:338-340` vs `:383-391`). After a list Check in answers `not_allowed`, hide or `aria-disable` the row buttons with the card's reason, as the scan tab already does with `notAllowed` (`:198`). Suggested: pass `notAllowed` to `ListTab` and render the status span (or a disabled button with `aria-describedby` the card) when it is true. One matrix case: off_team / list Check in &rarr; no enabled `door-row-checkin` afterwards.
4. **F4 (low) &mdash; `already_in` from the list leaves a stale "Check in" row** (`DoorScreen.tsx:92`). Invalidate the list on `already_in` too (the ticket IS in; the list is wrong). One line.
5. **F5 (low, copy &rarr; control) &mdash; the paused banner says "tap Check in" when the list could not load** (`:333-337` rendered inside `top` of the error branch `:354-357`). Either drop the banner when `list.isError && !list.data`, or word it "when the list loads".
6. **F6 (low, docs/tests) &mdash; role names.** INVENTORY &sect;3 and the handover say "admin / owner / editor"; prod `_is_entity_owner_or_editor` is `owner, manager, contributor`. Rename `editor` &rarr; `manager` in the matrix `ROLES` and the docs so the next reader does not conclude contributors are refused (they are allowed).
7. **F7 (low, claim accuracy) &mdash; "flag OFF is exactly main" and "208 failed / 10 passed".** Two reachable flag-off differences (check 1), both harmless; and the red-first run on this machine was 168 failed / 50 passed of 218, not 208 / 10. Reword the handover and PR body; or, to make the claim literally true, gate the `tried` reason line and the "Checking&hellip;" label behind `shortCodes`.

Not findings (checked and fine): `parseCheckIn` maps an unknown result to `unknown_code`, never `ok` (`data.ts:27`); `personOf` returns null for `too_many_attempts` so no stray name (`model.ts:137`); counts update from `too_many_attempts` replies (RPC returns counts, `DoorScreen.tsx:91`); row buttons are 44 px (`door.css:78`, e2e asserts the box); `door.css` only adds two rules on a class rendered behind the flag.
