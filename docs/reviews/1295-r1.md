## Ranked findings

### F1 (low, hardening) -- nothing pins `set -f`; without it a glob-only deletion can false-skip
`scripts/vercel-ignore-build.sh:147` (`set -f`) is load-bearing: `$BUILD_PATHS` holds
globs (`tsconfig*.json`, `.env*`, `vite.config.*`) that must reach git as pathspecs.
Mutant M6 (`set -f` commented out) **survives all 127 tests**. Reproduced the false
skip it allows: repo with `tsconfig.json` + `tsconfig.app.json`, head deletes
`tsconfig.app.json` only -> real script BUILDS (rc=1), mutant SKIPS (rc=0), because
the shell expands `tsconfig*.json` against the checkout (where only `tsconfig.json`
remains) and the deleted file is never asked about. Suggested test row in
`tests/vercelIgnoreBuild.test.ts`: seed `tsconfig.json` and `tsconfig.app.json`,
commit a deletion of the second only, expect BUILD. (A sibling-less deletion, e.g.
the only `.env*`, still BUILDS because sh keeps an unmatched glob literal.)

### F2 (low, hardening) -- the parser assumes the closing quote ends the assignment
`scripts/lib/buildRule.mjs:25` reads `^BUILD_PATHS='([^']*)'` and stops at the first
`'`. The shell keeps reading: `BUILD_PATHS='app src'" extra"` gives the parser
`[app, src]` and the shell `app src extra` (demonstrated locally). The single-
assignment test (`tests/buildRule.test.ts:70-73`) does not catch a same-line
concatenation, and the real-git agreement test (`:88-99`) passes the PARSED specs to
git, so it proves matcher == git-pathspec, not parser == shell. Direction of the
risk: a path only the shell knows is a build path -> the script builds (safe) but the
probe can go green on an ancestor's preview for a change under that path. Suggested
one-line pin: `expect(sh).toMatch(/^BUILD_PATHS='[^']*'$/m)` (closing quote ends the
line), or extract the value with `sh -c` and compare to `readBuildPaths()`.
Comments, line continuations and `#` inside the quotes were checked: the shell and
the parser see the same tokens for all of them (a backslash-newline inside single
quotes is a literal `\` token for both).

### F3 (info) -- the change cannot observe itself; first live proof needs a feat/* push
PR #1295 is on `claude/*`, so its own lighthouse / doc-weight / synthetic-preview /
seo-preview / og-preview jobs are skipped by `if:` and the Vercel build is turned off
by `vercel.json git.deploymentEnabled`. The by-diff skip and the probe's
ancestor-preview path have never run live. After merge, the first docs-only second
push on a `feat/*` PR is the real test: Vercel log should print
`vercel-ignore-build: SKIP -- no build path changed in <base> .. <head>` and the
lighthouse job should print `::notice title=preview by diff::`.

### F4 (info) -- 20-ancestor window
`scripts/lib/previewProbe.mjs:160` walks the newest 20 ancestors. 21 consecutive
docs-only pushes on one PR (each one commit, each skipped) make the probe red on
timeout (600 s) -- a false RED, never a false green. Acceptable; documented here so
nobody reads that red as a broken preview.

### 3. `findIdenticalPreview` never returns a preview of different app code
- Ancestor choice: `/commits?sha=<head>` lists commits reachable from head, so every
  candidate is an ancestor; newest with a READY `Preview` deployment wins (`:163-172`).
- `compare/<base>...<head>` must be `ahead` (`:179`); `ahead` means base is an
  ancestor and merge-base == base, so `files` is exactly the tree diff base..head
  (merge commits included: a merge of main lists main's files too, so a merged `src`
  change blocks the green).
- Truncation: `files.length >= 300` is doubt (`:179`, tested). No file list is doubt.
- Renames: `previous_filename` is included (`:183`, tested; mutant M5 killed).
- A READY preview of a different branch's later commit cannot be chosen: that commit
  is not an ancestor of head. Same-commit-on-two-branches gives the same code.
- `[skip preview]` heads throw before the ancestor walk (`:244-256`, tested).
- The head's own preview always wins and short-circuits the walk (`:263`, tested).
- Permissions: the compare and commits calls need `contents: read`; every preview job
  already grants it (perf-budget.yml:174-176, synthetic-ssr-monitor.yml:207-209,
  seo-check.yml:166-168, og-image-check.yml:249-251).
- Not modelled, pre-existing: Vercel env vars are not in git (handover says so);
  a second Vercel project on the same repo would already confuse `readyPreviewFor`
  before this PR (same `/preview/i` filter).
