## Findings (ranked)

### F1 medium: a server `used` answer is final, but the client still consults the same-name page list

- `src/modules/admin-organisers/join/joinModel.ts:98-101`, `join/JoinPage.tsx:85`, `:130-132`, `:143-151`.
- Read on prod today (read-only, `pg_get_functiondef`): `redeem_organiser_invite_v1` reads the caller's
  CURRENT `entity_members` row and answers `already_member` BEFORE the `used / revoked / expired` branch. The only
  thing that runs before that read is `_require_complete_dancer_profile_v1()`, which RAISES (the client maps it to
  kind `profile_incomplete`, `joinModel.ts:231,245`); it never returns `reason: 'used'`. So `{ok:false,
  reason:'used'}` means "signed in, past the profile gate, NOT on this team".
- The PR ignores that: after any refusal it falls back to `member` from `ownPageForName` (`JoinPage.tsx:85`) and
  `deriveJoinStep` turns `member === true` into `done` (`joinModel.ts:100`), then `returning` navigates to
  `doneTarget(..., doneOrgId)` where `doneOrgId` is the same-named page from the viewer's OWN list
  (`JoinPage.tsx:130-132`).
- Proof (failing test, run at `655c43f9`; signed in, preview used, redeem `{ok:false, reason:'used'}`, own list
  `[{id:'mine-not-the-invites', name: ORG}]`): expected the other-account dead screen, got
  `where = /account/o/welcome?o=mine-not-the-invites`. With P3 on it would be P3 Home carrying
  `state.confirmation = "You're on <org>'s team."` for a team they are not on.
- What it is NOT: the page is always one of the viewer's own (`organiser_home_v1` is caller-scoped), so nobody
  is sent to a page that is not theirs, and nothing on screen names who used the link (`USED_COPY.other_account`
  has no name or email; the card test asserts no `@`). Signed-out viewers never call redeem.
- The worker's own cell `joinJourney.test.tsx:797-799` ("redeemer (redeem refused, on the team by page list)")
  stubs the refusal as `reason: 'used'` and expects the redirect: it pins the wrong contract.
- Fix: keep the page-list fallback ONLY when `attemptRedeem` resolved `profile_incomplete` (or `failed` /
  network); on `kind: 'dead', reason: 'used'` set `member = false` and show `other_account` at once. Change the
  test cell's stub to the profile-gate refusal and add the same-name cell above as a red test.

### F2 low: the e2e gate assertions are weaker than needed (all three sites know the exact `back`)

- `tests/e2e/p3-gate-sheet.spec.ts:105`, `:155`; `tests/e2e/p3-gate-overlays.spec.ts:93`.
- Part 1's harness mounts at `/account/p3/events/x/details` (`tests/e2e/harness/gateHarness.tsx:39`), so
  `at` is that path and the href is exactly `...&at=review&back=%2Faccount%2Fp3%2Fevents%2Fx`. Part 2 and the
  overlays spec `goto('/account/p3/events/${FRIDAY}')` (`p3-gate-sheet.spec.ts:135`, `p3-gate-overlays.spec.ts:72`),
  so theirs is `&back=` + `encodeURIComponent('/account/p3/events/' + FRIDAY)`.
- `(&back=.*)?` accepts a MISSING back and ANY value (`&back=https://evil` included), so the e2e gate no longer
  proves slice R's link and would stay green under M1. The Review destination (`o=<ORG>&at=review`) is still
  asserted. Fix: the three exact strings.
