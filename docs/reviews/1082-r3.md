### 2. A landed step moves the version but not the base: after a half-landed two-step save, Undo then any edit silently reverts what landed (blocks merge) -- CONFIRMED by trace
- `src/modules/organiser/p3/screens/EditTray.tsx:46-49` (`landed` sets `opened.version` only), `:34` (`undo` =
  `setDraft(opened.base)`), `:53` (`saved` is the only place `opened.base` advances), `src/modules/organiser/p3/data/details.ts:161`
  (`name: draft.name.trim()` goes with every upsert).
- Sequence on Details: change the name ("Sensual Fridays" to "Friday Social") AND the chat link; Save. Step 1
  (`series.upsert`) lands at v8; step 2 (`series.set_group_chat`) is refused (finding 4 gives inputs the field accepts and
  the server refuses; a dropped connection or the 100/day cap do it too). The error line shows. The person taps "Undo my
  changes" and confirms. Now the draft is the base the screen OPENED with: Name reads "Sensual Fridays" under a page row
  (`DetailsScreen.tsx:85`, `ws.series.name`) that already reads "Friday Social"; tray empty; Save "Nothing changed yet";

- Then any later edit on the screen (say the description) sends `series.upsert {name: "Sensual Fridays",

## Checked and found fine
- Server key semantics (`_cmd_series_upsert_p5` UPDATE arm): every key the client can send is `CASE WHEN p_payload ? 'k'
  THEN ... ELSE <column> END`; absent = keep, present incl. null / '' / [] = set; `name` always written and required.
  `payment_methods: ''` parses to NULL with no problem; `[]` clears videos and passes; `''` clears ticket, cover, Instagram.
- Team price lists: 7 of 7 prod lists carry non-owner keys, so `pricesLock` holds, rows are `[]` on both sides, and
  `pricesPlan` never adds `default_passes` while locked; "how to pay" alone sends `{name, payment_methods}`. The stored list
  is never in a payload. `_owner_passes_problem_p5` matches `toPass` (uuid id, name 1-120, number or null, GBP/EUR/USD).
- Idempotency: replay on `(actor_id, idempotency_key)` only, before any lock, body ignored; the row is inserted only after
  the handler succeeds and a failure rolls back, so a failed key may be reused with any body. The client reuses a key only
  when the whole plan's JSON (`sig`, both step bodies) matches and `done < steps.length`; landed steps are skipped; `held`
  is cleared on success, on `version_conflict`, and by `forget()`. Version is not in `sig`, but nothing changes
  `form.version` under a held attempt (restart forgets; saved clears; landed only after `done >= 1`).
- Double tap: `setBusy(true)` runs before the first await and React flushes the click synchronously, so the button is
  disabled before a second click; a re-entry would reuse the same attempt and key and meet the row lock or the
  idempotency unique insert. No double apply. Transient failure: same key, same version; a lost response replays the
  stored success. Stale refusal, Start again, same edit: new keys at the live version (r2 #1 holds).
- `envelope()` drops `expected_version` when `version <= 0`; all 758 series are at version 1 or more.
- SessionSheet / `useEverySend`: `began` fixed at the first keystroke per scope; key id `${version}|${JSON.stringify(command)}`;
  key kept only on network failure; `sendDate` uses the programme version typing began on.
- Chat step goes against the version the upsert returned; `groupChatCommand` sends exactly `{url}` string or null; the
  owner arm and `_cmd_series_set_group_chat_p5` require that shape. `uploadFlyer` is Storage only (no version bump).
- Authority: `series.upsert` on an existing series and `series.set_group_chat` both need owner or manager
  (`_assert_can_edit_series_p5`, `v_owner_member_kinds`), never contributor; the client has no role gate, so a contributor
  gets the refusal copy, as in the old area. Keys the client sends are all in `v_owner_upsert_keys`; no `quantity`, no
  `format`. Server locks ENDED only; archived is a client-only lock (UX); draft locked by neither; festival handled the
  same both sides (ticket link only). Instagram: server regex equals client `INSTAGRAM_URL`; `instagramToSend` passes a
  stored URL through unchanged (query, trailing slash, case, dots, underscores survive).
- Leave guard: the Saved navigation never trips it (`saved` empties `changed` before `useBackToEvent` navigates); Back
  link, tab bar, browser back go through the one blocker; tab close through `beforeunload`; Sheet close resets the
  blocker. Clean tray hiding a change: remove the last price, It's free off, music cleared, videos cleared, whitespace-only,
  stored null vs '' all show and send. Undo resets the whole draft (venue, cover URL, rows and currency, methods) and
  clears `photo.error` and `save.error`.
- Scope: p3 is imported from outside only by `AnimatedRoutes.tsx:51` (`lazyWithRetry`, mounted only when
  `organiserP3 && organiserSelfServe`), a path string and the flag; Details and Prices are lazy inside P3Routes. No file
  outside `src/modules/organiser/**` and `docs/**` in the diff against main; `perf-budgets.json`, `vite.config.ts`,
  `vite.chunks.ts`, `AnimatedRoutes.tsx` untouched. `paymentModel.ts` and `seriesExtras.ts` are export-only.
- r2 #1 fix present (`isVersionConflict` drop, `forget()` wired on both screens).
