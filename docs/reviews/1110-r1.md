## Findings, most severe first

### 1. A locked price list (or a festival's fields) still has a live "use usual" link -- fix before arc end, CONFIRMED in code, PLAUSIBLE on data
`src/modules/organiser/p3/screens/DateSheet.tsx:131-135` (`OwnRow`) and `:270-276`. `why` replaces only
the "Change for this date" link; the `own && (... use usual)` block above it ignores `why`. So:
- Price row, date's own list team-shaped (`datePricesLock(ws, detail)` non-null): the row reads
  "This price list was set up by the team, so it can't be changed here" while "use usual" one line
  above sends `{ passes: null }` and throws the team's list away (the server accepts null for any
  owner key). Input: `detail.passesOverride = [{ id, name: 'VIP', price: 40, tier: 'vip' }]`.
  0 such rows on prod today (passes override has never been set), hence PLAUSIBLE on data.
- Name / Photos / Price rows on a festival (`dateFieldsWhy`): the reason says they are the whole
  festival's, "use usual" still clears an own value; `apply_aggregate_write_p5` has no festival gate
  on `set_override`, so it goes through. 1 festival override row on prod, none with these keys.
Fix: pass `why` into the `own` block too (grey the link with the same reason), or hide "use usual"
when `why` is set. The design record's "kept as intended" covers the greyed row, not this link.

### 2. The blank-name reason points at a control that is not on the sheet -- fix before arc end, CONFIRMED
`src/modules/organiser/p3/model/labels.ts:308` `dateNameBlank`: "Give this date a name, or use the usual
name". On the Name sheet (`DateFieldSheets.tsx:76-87`) there is no "use usual": that link is on the
dayown row, a step back. Input: open Name, select all, delete -> the held reason (`p3-field-why`)
names a control the person cannot find. The fix round removed the same pointer from the two empty
states (handover) but left this one. Fix: "Give this date a name" (Undo my changes already restores
the base), or add a "Use the usual name" link in the sheet that sets the text to the series name.

### 3. An abandoned Photos edit leaves orphan objects in storage -- nit (storage, not data), PLAUSIBLE
`DateFieldSheets.tsx:98-111`: each picked file goes to the bucket at once via `uploadEventPicture`
(`events/media.ts:9-18` -> `uploadFlyer`); the date only references it when Save sends the list.
"Leave without saving", "Undo my changes", Escape/scrim + leave, or a refused save never retried all
leave the uploaded objects unreferenced. `flyerUploadApi.ts` has no remove path. W2b's cover photo
(`DateSheet.tsx:329-345`) uploads and saves in one go, so it has no such window; the series gallery
editor was not checked (same path, probably the same litter). No partial list is ever sent (only
Save sends, with the full current list) and a failed upload keeps the photos already there (test
`w3b2.send.test.tsx:189-212`). Not this PR's to solve alone; worth a line in the PR body.

### 4. The geometry spec's "no page scroll" assertion cannot go red -- nit, CONFIRMED
`tests/e2e/p3-w3b2-geometry.spec.ts:74` asserts `window.scrollY === 0`, but the page it mounts puts
everything under `.p3-frame` (`position: fixed; inset: 0`, `p3.css:49`): the window never scrolls, so
the assertion holds whatever the sheet does. The real scroller is `.p3-main` (`overflow-y: auto`), and
the sheet is not inside it, so focusing a sheet button could not scroll it either. The `Sheet.tsx`
`focus({ preventScroll: true })` change is therefore harmless to the W2b/W2d/W3a sheets (same
component, same reason) but also unproven by this spec. The spec is otherwise sound: it would go red
if the sheet left the viewport (lines 70-73), on sideways overflow (75-76), on a tap under 44px (77)
and on tiles outside the sheet (81). It is a hand-copied markup mirror of the component, tied to it
only by the three `className` pins in `w3b2.send.test.tsx:194-196`.

### 5. Brief line "Sheets portalled to `document.body`" not done -- nit, CONFIRMED, declared in the handover
Not a geometry defect at 390x844 or 360x640: `.p3-frame` has no `transform`, `filter`, `contain` or
`will-change` (grep of `p3.css`), so the `.p3-scrim` `position: fixed` inside it is viewport-positioned
and the e2e proves the box. The one effect: the scrim (z 70) lives inside the frame's stacking
context (z 60), so only things mounted inside the frame can stack against it; everything P3 mounts is
inside it (`EventPage.tsx:217`, `AllDatesScreen.tsx:62`). Owner call; I would accept the deviation.

### 6. A cancelled date that owns only a name/photos/price offers "Put this date back to normal" live -- nit, CONFIRMED
`p3/model/dates.ts:110` pushes `row('resetNormal', base)` with no cancelled reason; `resetNormalPlan`
(`p3/data/dates.ts:171-175`) correctly leaves the three keys out on a cancelled date (prod
`c_a3_cancel` refuses them by key presence, even null), so the plan is null and the confirm sheet's Go
is disabled with `L.dateFieldsCancelled`. The control is disabled with a reason, one tap late. 1 prod
row has this shape (a cancelled date with a title). Could grey the list row with the same reason.

### 7. Copy: "photo" and "photos" side by side -- nit, CONFIRMED
`labels.ts:124-125`, `p3/data/dates.ts:219`: "Where, about, ticket link, photo, name, photos, price".
"photo" is the cover, "photos" the gallery; a reader cannot tell. "cover photo" (or "flyer") for the
first would do. British English, full weekday names (`fullDate`), entities and `\u` escapes only in
the diff otherwise hold.

### 8. Doc drift -- nit, CONFIRMED
- `dateFields.ts:11-12` says the fields read back as `event.name`, `photo_urls`,
  `meta_data_public.tickets`; `event_view_p5` emits `event.name`, `event.gallery`, `event.passes`
  (the other names are the snapshot/compat reader's).
- Handover and `parity-matrix.test.ts:92` call `v_owner_override_keys` a prod object; on prod it is a
  plpgsql constant inside `apply_aggregate_write_p5` (no relation of that name exists). The list is
  the same 10 keys, so the mirror is right.
- Handover "No new `COMMAND_COPY` rows for the title / gallery / passes owner refusals": rows already
  exist, `selfServeErrors.ts:189` (`occurrence_cancelled`), `:199` (title), `:201` (gallery), `:215`
  (passes). So judge-point 7's "generic fallback" does not arise. (`:199` says "or leave it empty to
  use the event name", a path the client never offers; pre-existing.)

### 9. Save button reads "Nothing changed yet" on a dirty-but-equivalent draft -- nit, CONFIRMED
`DateFieldSheets.tsx:68`: `dirty` is `sameValue(base, draft)` on raw rows (trims a string, not a
string inside an object); `patch` compares `toPass` output (trimmed). A price name with a trailing
space is dirty with no patch and no problem: the button says "Nothing changed yet" while "Undo my
changes" shows. Cosmetic.

## What was checked, point by point (brief "Judge")

1. **Send correctness.** `_cmd_occurrence_set_override_p5` (prod): a key absent from the payload keeps
   `v_existing.*` (`v_title := CASE WHEN p_payload ? 'title' ... ELSE v_existing.title`; same for
   gallery and passes), JSON null -> SQL NULL = inherit, `[]` -> `'{}'` text[] / `[]` jsonb = owned
   (`_occurrence_override_key_set_p5` ownership is `IS NOT NULL`). `overrideCommand` sends only the keys
   in the patch, arrays as they are, null for inherit; each builder returns ONE key or null; an
   untouched save has `patch === null` so Save is disabled and nothing is sent. `[]` vs null: `??`
   on `galleryOverride`/`passesOverride` keeps `[]` (3 owned-empty galleries on prod), the "removing
   every photo sends []" test pins it. Blank name is held (`dateNameProblem`), never sent as `null`.
   Version: `PLAN.details(d, patch)` carries `d.version`; `envelope` adds `expected_version`; prod
   raises `version_conflict` on mismatch. Retry: `KeyRing` keys on `[occurrenceId, commands]` without
   the version, so the retry replays (test `w3b2.send.test.tsx:145-157`). Stale version: the sheet
   stays mounted with the draft, `VERSION_CONFLICT` copy shows, `useSendPlan`'s `finally` reloads the
   workspace so the next Save carries the new version.
2. **Data loss.** Editing one key never carries another (handler above). `resetNormalPlan` stays one
   `set_override` + optional `set_time`; the three keys ride the same command (test :306-314).
   Cancelled: `c_a3_cancel` on prod refuses `title|music_styles|gallery|passes` by key presence
   (`?|`), even null; other keys are still allowed on a cancelled date, so leaving only these out is
   exactly right. Past dates: prod refuses `set_override` on a past date for owners; 52 such
   override rows exist; the UI greys "Different details" on a past date (`dateActions` `past`).
   Title equal to the series name (2 prod rows): shows as own, typing it again sends nothing, "use
   usual" sends `{title: null}`.
3. **Locks.** Festival rows grey with reason; team-shaped list (series or date) greys Price with the
   W3a reason; a date list is never silently editable and never hidden. Except finding 1.
4. **Photos.** `uploadEventPicture` is the series path (check, bytes, re-encode, upload); failure keeps
   the list and shows the copy; order kept (append); cap: `files.slice(0, MAX_GALLERY - n)`, Add hidden
   and a note at 30 (`MAX_GALLERY` 30 = prod `c_owner_gallery_max`); remove buttons 44px with numbered
   labels; partial list never sent. Finding 3 for orphans.
5. **Leave guard / Undo.** Close (header, scrim, Escape), Back: guarded when dirty or uploading and not
   busy; Undo asks then restores the base and sends nothing; focus lands on "Keep editing"
   (`autoFocus`, test :227-241). `preventScroll` in the shared `Sheet`: harmless to every P3 sheet
   (finding 4).
6. **Overlay geometry.** Findings 4 and 5.
7. **Parity.** `OWNER_OVERRIDE_KEYS` = prod `v_owner_override_keys` minus `music_styles` (deferred,
   declared in the matrix); `check_owner_command_allowlist_v1` asserts the same literals and probes
   blank/81-char title, `[""]` and 31-URL galleries, a pass without `id`, 11 passes. Pass shape:
   `toPass` emits `{id, name, price (number|null), currency, description?}`; `_owner_passes_problem_p5`
   requires `price` present (null ok), uuid `id`, name 1-120, price `^[0-9]{1,6}([.][0-9]{1,2})?$`
   -- `Number('12.50')` serialises as `12.5`, which matches. Copy exists (finding 8).
8. **Copy and a11y.** Findings 2 and 7. Taps: `--tap: 44px`, `.p3-link`/`.p3-btn`/`.p3-photo-x` use it.
   Accept list = JPG/PNG/WebP, matching the hint.
9. **Flag-OFF and scope.** New files are imported only from `DateSheet.tsx` and `PricesScreen.tsx`
