## Verdict: HOLD (SHIP-AFTER-FIXES once F1 and F2 land; merge only after Part B is live)

The owner / manager split is in the right places and the client never shows an amount to a manager. But the
headline PQ1 copy for managers is dead in production (F1), the tests pass only because their fixtures carry
pence the real manager read no longer fetches, and one money block survives its mutant (F2). On network
shape the PR is honest about orders but not about the sales summary: a manager's browser still receives
every `*_pence` field from `ticket_sales_summary_v1` on both screens (F3), which only Part B can close.

**May it merge before Part B?** No (the PR body says the same). In the gap a manager can: refund any order
through `ticket-refund` (edge function admits owner and manager, INVENTORY.md section 1), read every
`ticket_orders` money column, `buyer_email` and full `buyer_name` by RLS, and get per-type `gross_pence`,
`refunded_pence`, `discounts_pence`, `booking_fees_pence` from `ticket_sales_summary_v1`. The client hides,
the server does not refuse.

## Findings (ranked)

### F1 blocker: a manager never sees "Ask the owner to refund this order." in production

- `src/modules/organiser/p3/tickets/TicketsEntry.tsx:298` renders `tix-refund-ask-owner` under
  `manager && !owner && refundable(o)`. `refundable` (`ticketModel.ts:588`) is
  `status === 'paid' && totalPence - refundedPence > 0`.
- The same PR makes the manager's read counts-only: `TicketsEntry.tsx:157` passes `canRefund(org.role)` so
  `fetchOrders(typeIds, { money: false })` selects `ORDER_SELECT_COUNTS` (`ticketsApi.ts:148`), and
  `parseOrderRow` turns the missing columns into `0`. So for a manager every order has `totalPence 0`,
  `refundable(o)` is false on every row, and the note never renders. The legacy-row note `tix-refund-reason`
  (`TicketsEntry.tsx:334`, `!manager && shown.some(refundable)`) is dead for the same reason.
- Why the suite is green: `tickets.roles.matrix.test.tsx:27-31` builds the manager's orders with the
  `order()` fixture (`fixtures.ts:86-98`: `totalPence 2500`), i.e. the OWNER payload, and the harness mock
  of `useSeriesOrders` returns it unchanged for every role (`harness.tsx:47-50`).
- Proof (run at `7debc56` in a scratch worktree, then deleted): a copy of the roles test that feeds the
  manager `parseOrderRow` rows shaped like `ORDER_SELECT_COUNTS` (no pence keys) and asserts
  `tix-refund-ask-owner` on the paid row: **fails**, `expected null not to be null`.
- Fix: gate the manager's note on status alone, e.g. `export const refundableByStatus = (o) => o.status === 'paid'`
  in `ticketModel.ts` and use it at `TicketsEntry.tsx:298` and `:334` (the owner's button keeps
  `refundable`, which needs the pence). Then make the roles test honest: build the non-owner rows through
  `parseOrderRow` from count-shaped rows (or strip the pence in `dataMock.useSeriesOrders` when `money` is
  false), so the fixture matches the read the screen really makes. This also turns `tix-counts-only` /
  `tix-order-line` cells into real counts-only tests.

### F2 should-fix: Money so far on Get paid is shown to a manager by one word, and no test notices

- `src/modules/organiser/p3/tickets/GetPaid.tsx:194` `{owner && types && types.length > 0 && <MoneySoFar/>}`.
- Mutant (b), `owner &&` removed: `getPaid.matrix.test.tsx`, `tickets.roles.matrix.test.tsx` and the rest
  of the touched specs stay GREEN (1418 of 1418). The two manager rows added at `getPaid.matrix.test.tsx:29-31`
  check only the button and the why line; the one `tix-money` null assertion (`:103`, `:109`) runs for the
  contributor shape whose summary is `refused`, so `types` is null and MoneySoFar is not reachable anyway.
- Fix: in the manager rows assert `queryByTestId('tix-money')` is null, `tix-setup` is null and
  `tix-money-error` / `tix-money-refused` are null, with a summary that carries sales (`SHAPES.selling`'s
  `sales`) so the block WOULD render for an owner.

### F3 should-fix (Part B, name it in the PR): a manager still receives pence from `ticket_sales_summary_v1`

- `TicketsEntry.tsx:161` `useSummary(org.id)` and `GetPaid.tsx:126` `useSummary(org.id)` run for every
  role; `fetchSalesSummary` calls `ticket_sales_summary_v1`, which on prod today returns `gross_pence`,
  `discounts_pence`, `booking_fees_pence`, `refunded_pence` per type to owner, manager and contributor
  (INVENTORY.md section 1, gate `_is_entity_owner_or_editor`). The client uses only `ticketsSold` for a
  manager (`TicketsEntry.tsx:203-204`), but the money is in the response body and in the react-query cache
  under `ticketKeys.summary(organiserId)` (same key for every role). Check 4 is a FAIL on network shape for
  this call; there is no count-only source today, so this is Part B work. Fix for the Website PR: say so in
  the PR body's NOT verified (it names the RPC but not that the client still calls it for a manager), and add
  a test that the manager's summary parse drops the pence fields client-side (defence in depth) once Part B
  defines the manager payload.
- The orders read is honest: `ORDER_SELECT_COUNTS` has no pence column and its own cache key
  (`data.ts:73`, `'money' | 'counts'`), test `ticketsMoney.matrix.test.ts:96-117`. But it still selects
  `buyer_name` (the FULL name) for every role, and `buyerFirstAndCode` trims it client-side. Q14 says full
  names are not shown to organisers; the payload carries them. Part B item (a first-name column or view).

### F4 should-fix: `refundQuestion` and the toast show the short code, but it is not the buyer's code

- `ticketModel.ts:594` `orderShortCode` = first 4 characters of the order id. The buyer's ticket carries a
  different `short_code` (`src/modules/tickets/myTicketsModel.ts:89`, door `classifyCode`). An organiser
  reading "Ana · 3F2A" to a buyer, or a buyer quoting their code, will not match. The Sales report CSV uses
  yet another one, `shortRef` = 8 characters (`salesReportModel.ts:119`). Two codes for one order, neither
  the buyer's.
- Fix: reuse `shortRef` (one mapping, 8 characters) now, and in Part B expose the ticket `short_code` on the
  orders read if the label is meant to be said aloud at the door.

### F5 note: the ask-the-owner note is a flex sibling of the buyer column

- `TicketsEntry.tsx:298-300` puts the `<p>` inside `li.p3-row` (flex, `p3.css:94`) next to `.p3-grow`.
  Its max-content width (~230 px at `--fs-small`) squeezes the buyer / line column at 390 px. No sideways
  scroll (`p3-grow` has `min-width: 0` and the note wraps), but it reads as a second column, not a note under
  the row. Not walked. Fix: render it inside `.p3-grow` under the tags, or give the li `p3-row-col`.

### F6 note: `SalesReport`'s `money` prop defaults to `true`

- `SalesReport.tsx:18` `money = true`. Only one caller today (`TicketsEntry.tsx:467` passes `money={owner}`),
  but a future caller that forgets the prop leaks money. Make it required.

### F7 note: `NOT_MANAGER_STRIPE` now aliases the ask-the-owner copy, and the `not_authorised` reply says "owner or manager"

- `ticketModel.ts:62` `NOT_MANAGER_STRIPE = PAYOUTS_ASK_OWNER`: harmless (no importer outside the GetPaid
  test), but a dead name; delete it.
- `REASON.not_authorised` (`ticketModel.ts:709`) stays `NOT_MANAGER` = "Only an owner or manager of this
  page can change tickets." Today the edge function answers a manager's refund with `not_authorised` only
  when they are NOT a manager; after Part B a manager gets `not_allowed` -> `NOT_OWNER_REFUND`. The one place
  `not_authorised` can reach a refund toast is an owner whose seat was removed mid-session: "owner or
  manager" is then slightly wrong (it should read "the owner"), but it is not a pointer at a missing control.
  Fine to leave; note it in INVENTORY.md.

### F8 note: the "legacy contributor" role cannot occur on these screens today

- `HomeOrganiser.role` is `'owner' | 'manager'` (`src/modules/organiser/shared/selfServeApi.ts:44`), the
  fixtures cast `'contributor'` past it, and prod `entity_members` (entity_type organiser) holds 21 owner and
  43 manager rows, no contributor. The P11 cells are tested against a shape the home read never produces.
  Keep them (A1 says test as legacy rows), but the INVENTORY should say the role is unreachable on prod.
