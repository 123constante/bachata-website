## The ONE save model (for W3b / W3c)
- `p3/model/saveModel.ts` (pure): `FieldSpec`, `changedKeys`, `pendingLines`, `saveButton`, `attemptFor` /
  `stepLanded` (one idempotency key and version per command, reused by a retry; a landed step is skipped),
  `changedElsewhere`.
- `p3/screens/EditTray.tsx`: `useEditForm` (draft vs the base it opened with; a version that is not this
  screen's own keeps the typing and shows `L.changedElsewhere` + "Start again from the saved version"),
  `useSaveRun` (sends through `useSendOnce`; refusals via `commandErrorMessage` = `COMMAND_COPY`),
  `EditTray` (tray, Undo confirm, leave sheet), `GuardedBack`, `useBackToEvent`.
- Leave guard reuses `areas/shared` `useLeaveGuard` + `useAreaLeaveBlocker` (no second blocker).
- A screen supplies `specs`, a draft builder, a blocker and a plan. Untouched = no pending line = Save off
  = nothing sent.
- One command per save, except a chat link change, which the server stores behind its own command
  (`series.set_group_chat`): a save then sends the upsert and then the chat command against the version the
  upsert returned. Each keeps its own key; "Try again" resends only what did not land.

## Known limits
- Gallery (photos beyond the cover) and the default level are not on Name and details (level is null on
  every prod series; gallery stays in the current area).
- A stored ticket link that breaks today's rule (2 live events) shows its problem but does not block other
  saves; it is only checked when changed.
- Stages 5/6 (owner screenshots, phone) are the orchestrator's.
- The cover photo is uploaded as soon as it is picked; "Undo my changes" (or leaving) puts the old cover
  back in the draft but does not delete the uploaded file (an orphan in storage until a clean-up job
  exists). Undo does clear the photo's problem text (r1 #7).
- A festival whose stored payment codes include `free` (0 of 13 on prod, read 2026-10-27) shows no
  "It's free" switch; its ticket-link chip still saves and drops `free` (pinned in w3a.r1.matrix, r1 #5).
