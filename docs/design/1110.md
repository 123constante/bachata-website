# Design record: PR #1110, P3 W3b-2 per-date Name, Photos and Price

Source drawing: C3 sheet `dayown` (the W2b "Different details this date" sheet). The C3 file itself
(`docs/organiser-rebuild/p3/mockups/C3.html` on `claude/er-p3-c3-test`) was NOT opened in this
session; the rows below are matched against the W2b build of `dayown`, which followed C3, and the
brief `briefs/p3-w3b2.md`.

| C3 / brief element | Built | Matches C3 / does not and why |
|---|---|---|
| `dayown` rows: label, "Only this date" / "Same as usual" chip, value, "Usually: ... &middot; use usual", "Change for this date" | Three more `OwnRow`s under Where / About / Ticket / Photo: **Name**, **Photos**, **Price** | Matches: the same row component, chip and links as W2b. |
| Name row value | The date's own name, else the series name | Matches. |
| Photos row value | "3 photos" / "No photos" (a count, not thumbnails) | Does not draw thumbnails in the row: density rules, and the photos sheet shows them. |
| Price row value | "Entry GBP-sign 12 &middot; Door ..." from the series price rules; "N prices are on the event." for a team-set list | Matches the W3a Prices wording; the locked case reuses `L.pricesLockedCount`. |
| Festival | Name, Photos, Price rows grey: reason line instead of "Change for this date" | Brief: not offered on a festival, with a reason. |
| Team-set price list (series or date) | Price row grey with the W3a lock reason | Not in C3; the server would refuse those keys (`_owner_passes_problem_p5`), so no live control. |
| Edit sheets | "Name" (one input, 80 max), "Photos" (3-across grid, 44px remove, "Add photos"), "Price" (the W3a `PriceCard`, now shared in `PriceCard.tsx`, "Add a price") | C3 has no separate drawing for these; they follow the W2b About / Ticket sheets and the W3a Prices rows. |
| Save model | Save is "Nothing changed yet" (off) until the draft differs from the base and the builder would send something; a held change names its reason; "Undo my changes" and Back / Close with a change ask first | The W3a model (`saveModel` `sameValue`) inside the W2b sheet; not the W3a page tray, because a date's fields save one at a time like W2b's Where / About / Ticket. Stated in the PR. |
| "Put this date back to normal" | The SAME W2b composite (`resetNormalPlan`), now also sending `title`, `gallery`, `passes` as null | Matches; no new command. On a cancelled date those three are left out (the owner arm refuses them there) and the sheet says so. |
| Per-date music | Not built | Brief: waits for admin A2 R4 (calendar reader). |

Tokens: existing P3 tokens only (`--fg`, `--sheet`, `--card2`, `--r-date`, `--tap`). New CSS: `.p3-photos`
(3 columns), `.p3-photo` (4:3 tile), `.p3-photo-x` (44px tap). Contrast rows added in
`p3Theme.contrast.test.ts`. Geometry (inside the viewport, no page scroll, no sideways scroll, 44px taps,
3 across) asserted by `tests/e2e/p3-w3b2-geometry.spec.ts` at 390x844 and 360x640, light and dark.
