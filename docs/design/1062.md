## Brief
- **Who:** an organiser on a phone (390x844), on one of their events.
- **One job:** change ONE date (cancel or bring back, move, time, skip a week or put it back, its own
  Where / About / Ticket link / photo, back to normal) or add a date, and see every date on one screen.
- **Feel:** C3 date sheets (`dayown`, `dtime`, `adddate`, `skip`, `resetdate`, `cancelnext`) in the
  existing P3 bottom sheet; greyed WITH the reason, never hidden.

Mockup C3 (`claude/er-p3-c3-test`, `docs/organiser-rebuild/p3/mockups/`), sheets `dayown`, `dtime`,
`adddate`, `skip`, `resetdate`, `cancelnext`. CONTRACT section 2 (date rows). Server rules read from

handlers `_cmd_occurrence_cancel/move_date/set_time/set_override_p5` and

## What matches C3, and what does not (and why)
| C3 / brief | W2b | Why |
|---|---|---|
| Date sheet with every action for that date | Same, ONE rule set `model/dates.ts` `dateActions` (kind x date state), each greyed with a `DATE_WHY` reason | Brief item 4; one rule set, never hidden |
| "More for this date" fold | No fold: every row visible | A folded greyed row hides its reason |
| "Remove this date" | Listed, ALWAYS greyed: "Dates are never deleted here&hellip; Cancel it instead." | Owner answer 20 (wave B0, `moveNotRemove.matrix.test.ts`); owner call 2026-10-27 keeps the guard; `series.remove_date` not built |
| `resetdate` "Put this date back to normal" | `set_override` nulls + `set_time` reset (composite, keys kept per plan); sessions stay | C3 says sessions stay; per-date sessions are W2d |
| "Add another date" on a one-off | Greyed: "A one-off has one date. Move it, or make a new event&hellip;" | Server date rules; a one-off holds one date |
| "Class n of N" on a course date | Not shown | A2 R2 not landed |
| `adddate` / move calendar | Native date input + day check (`pickDayProblem`: past, taken incl. cancelled) | Native picker is the phone's own; the taken check runs before sending |
| One-off "Cancel the event" | Opens THE W2c `CancelEventSheet` (`series.cancel_one_off`), label `L.cancelEvent` | Brief item 2: one control, one mapping |
| Festival move / time | Greyed with the reason (server refuses) | Brief item 4 |
| Sheet title "Friday 30 October, 9pm" | Uses the shared `timeWord` ("8pm"), as the event head | Walk found "20:00" next to "9pm" on the head; fixed, pinned by `dates.send.test.tsx` (red first) |
| "All dates" | `events/:id/dates`: 5 filters with counts, honest "newest 100 of N", empty state per filter says what to do | Brief item 3; no client paging from a second read |
