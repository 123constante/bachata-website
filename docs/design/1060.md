# Design record: PR #1060, S3b organiser ticketing redesign (2026-10-27)

Brief: `brief/ticketing-organiser-ui` `briefs/ticketing-organiser-redesign.md` (blob b5e3618). Flag
`organiserTicketing` stays OFF. Dispatch ticket `dt_57ce27a0ca93`. Stages 5 and 6 are the orchestrator's.

## Brief
- **Who:** an organiser on a phone (390x844) selling tickets for the first time, or checking sales.
- **One job:** connect payments, add a ticket in three short steps, put it on sale, and see / refund orders.
- **Feel:** the owner picked **Option B, Compact** from the two mockups:
  <https://claude.ai/artifact/7NicJi37hDk21cUSG239ZD> (the "Option B: Compact" row). Dark organiser area,
  existing tokens only (`ember.css`), one Next step card, denser lists, numbers sooner.

## What matches B, and what does not (and why)
| B mockup | Built | Why |
|---|---|---|

| Payments switched off server side | After Connect returns `not_configured`, the button is replaced by plain words and "Add a free ticket instead" | Brief: no dead button. The site cannot know before the tap (edge function 404 / 503) |

| 2. Chip "Paid out via Stripe", Sold and Sales cards, chip Selling, "8 left of 20", highlighted card with Add tickets | Same. One line under the numbers carries the rarer facts (refunded, waiting for payment, disputed) and "before Stripe's fees" | S3 showed those counts; kept, compact |

## Stage 4: self-running checks (this session)
- **Matrix:** `screens.matrix.test.tsx`, 64 tests: Home and One event x 12 shapes (no payments, payments
  pending, connected no tickets, draft only, selling, paused, sold out, free ticket, paid draft pending,
  contributor read-only, closed, API error), the add sheet x every manager shape x paid / free, the refund
  sheet x every refundable shape, and the flows (Put on sale, Save as draft, untouched edit sends nothing,
  price lock, read-only, switch, refusal words, `?add=1`, Event start default, unreadable summary,
  not-switched-on Connect and Refund). Expected values come from `ticketModel`, never a copy.
  `compact.model.test.ts`: buyer total, switch, event state, setup x Next step (role x Stripe x tickets),
  order line / days (BST and GMT), step errors, closes words, the upsert id. Mutation check: two planted
  bugs (chip always shown, Refund for contributors) each turned the matrix red.
- **Taps:** every control measured in the browser at 390x844 and 360x640: none under 44px in the ticketing
  area (the only small links are the site footer's, not this area). The switch is 44x64; px sizes, not rem.
- **Contrast:** no new colour pairs except the destructive button (`--danger` #ff7a6b fill with `--btnfg`
  #1d0a03 text, the pair `LifecycleActions` already ships) and `--gold-fg` link text on `--card`.
- **Copy:** British English, punctuation as `\u` escapes or HTML entities (no raw Unicode in source).
- **Walk at 390x844 and 360x640** (dev server, the phone suite's fake Supabase plus ticket rows shaped like
  the live RPCs): 10 screens each, no sideways scroll, no page errors. 390 screenshots in
  `docs/handover/ticketing-organiser-ui/`. They were taken just BEFORE the full-month fix, so an older
  order there reads "20 Oct"; the code now says "20 October" (unit-tested, not re-shot).
