# Design record: PR #977, invite W2 (phone + Instagram fields, "Do you also teach or DJ?", "It's live")

## Stage 1: brief
- **Who:** an organiser publishing their first event, on a phone (390x844).
- **One job:** publish without being asked twice; store the phone as E.164 and Instagram as the bare name.
- Source: `brief/invite-journey` `briefs/invite-journey/W2.md` and PLAN.md section 4 "W2".

## Stage 2: prototype (owner approved 2026-10-23)
https://claude.ai/artifact/RRXU7H3ZaLvD4PFnx14MAu (the publishing prototype): phone and Instagram fields,
"Do you also teach or DJ?" in "Almost live", the "It's live" offer, teacher page before/after.

## Stage 3: build
The fields are the ONE shared `PhoneInput` / `InstagramInput` (`src/components/forms/`). They are used in the
wizard steps, so in "Almost live" too, in the organiser contact sheet and in the raffle. The roles question is
`golive/RoleQuestionScreen.tsx`. "It's live" is `flows/Done.tsx` + `ItsLiveOffer.tsx`. The dancer edit screen's
use of them is split out of this PR (it is a dancer-area change), see the handover.

## Stage 4: self-running checks (390x844, dev server, the phone suite's fake backend)
Spec: `tests/e2e-phone/invite-w2-golive.phone.spec.ts` (W2d: 15 tests, the go-live screens plus the Contact details
sheet and the raffle). It runs on every screen below, in CI's phone-qa job too. The phone box is typed key by key
(`pressSequentially`), never `fill()`: `fill()` hid blocker 1 of the critique. Go-live data comes from `goLiveRpcs(scenario)` in `tests/e2e-phone/fakeSupabase.mjs`,
served browser side only via `fakeSupabase(page, { goLive })`.

| Check | How | Result |
|---|---|---|
| Text contrast >= 4.5 | axe `color-contrast` on `main`; on the sheet / raffle dialog (in `document.body`, outside `main`) axe is scoped to the dialog | PASS, 0 violations on every screen |
| Taps >= 44px | every visible button / link / input in `main`, in the whole sheet, and in the raffle phone field (input, country button, first 12 country rows) | PASS, none under 44px |
| No clipping | screenshots reviewed: long link in the Instagram box, two-line legacy note, offer cards | PASS |
| No sideways scroll | `checkOverflow` (same as the other phone specs) | PASS, every screen |
| Empty / loading / error states actionable | empty phone: Continue says why it is refused (the hint); short phone: Continue shows the field's own line, "Looks short. United Kingdom numbers have 10 digits after +44."; invalid Instagram: the rule on screen; roles unanswered: Continue off with its reason; gaps: each one is a link to the editor that fixes it, and Go live says "Finish the list above first."; loading and load failure: "Try again" (unit tests `GoLiveFlow.test.tsx`, `GoLiveRoles.test.tsx`) | PASS |
