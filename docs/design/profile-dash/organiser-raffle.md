## The two ideas

| | **A: a switch in each night** | **B: a raffle page per night, one button** |
|---|---|---|
| Events list | One plain line under the night: "Raffle &middot; 23 entered", "Raffle winner: Ana Example" (no line when off) | A chip on the right: Raffle open / Raffle locked &middot; 23 / Winner drawn |
| Night sheet | "On the night" card: **Raffle** row with an on/off switch, the status line and one sentence of what it means; Tickets row under it | "On the night" card: **Raffle** row with its chip; tap opens the Raffle sheet |
| Changing it | Flip the switch -> confirmation sheet (hard stop) | ONE button for the only thing possible now: **Open a raffle** / **Close the raffle** / **Message us to cancel** -> same confirmation |
| Locked | Switch stays on, greyed with a dashed edge; reason + **Message us to cancel** | 4-step track at "Entries"; the button IS "Message us to cancel" |
| After the draw | Same card grows three facts: Winner, Drawn, Entries | Track at "Winner"; status box + facts card (Entered, Winner, Drawn) |
| Taps to open a raffle | night -> switch -> confirm (3) | night -> Raffle -> Open -> confirm (4) |

Shared (one function each in `core.js`): phase mapping (`phase`), status story (`story`), the gate that says
why a control is off (`gate`), the confirmation copy (`confirmBody`), contributor banner, save-failed banner,
loading, error, empty.

**Confirmation copy (both).** Open: "It shows on this night's event page straight away. Dancers can enter
until 7pm, 2 hours before the start. **Once anyone enters, you cannot close it here.** To cancel after
that, you message us. We draw one winner and tell them. You let them in free on the door." Buttons **Open
the raffle** / **Not now**. Close (only while nobody has entered): "It comes off this night's event page now.
Nobody has entered, so nobody is told. You can open it again until 7pm." Red **Close the raffle** / **Keep it open**.

## Careful lane (admin repo, before either option can ship)

1. **Organiser read** `organiser_raffle_nights_v1(organiser_id, from, to)`: per night: effective on/off
   (`COALESCE(raffle_nights.enabled, series.raffle_enabled)`), close time, entries count, locked, winner name
   and draw time. Gate on organiser membership (owner / manager / contributor read; contributor read is
   an ACL decision, same as the Team careful lane 4). Today every v2 RPC is `_raffle_v2_require_admin()` only.
2. **Lock rule "once anyone has entered"** server-side, replacing / adding to `holds_locked_win`.
   Needs a definition of "entered for this night" in the pool model (G1).
3. **Per-night entries count** + a snapshot of it on the draw, so the drawn night keeps "41 entries" (G2).
4. **Organiser write** `organiser_raffle_night_set_v1(occurrence_id, enabled)`: owner (and manager?) only,
   refuses when locked, past the close time, cancelled or draft; writes `raffle_nights` with `set_by`.
   Opening / closing is a **hard stop for the owner in automation**: no agent or bulk path may call it.
5. **Wins carry their night**: `raffle_wins.occurrence_id` is NULL on all 16 prod wins; the draw must set it,
   or "winner per night" cannot be shown (G5).
6. **Which winner name an organiser sees** (first name only like the public board, or full name for the door)
   and only once the win is locked / attended (raffleWinState.ts). Privacy decision.
7. **"Message us to cancel"** needs a destination (WhatsApp / email / in-app) and our cancel path
   (`admin_raffle_night_set_v1` refuses while a win is locked; cancelling with entries needs telling the pool).
8. **Series default vs per-night**: today 53 series are on and 0 nights are overridden. Decide whether
   switching a series on still opens every future night (what organisers then see as "on" without having
   confirmed each night), or whether the organiser path only ever writes per-night rows.

## Recommendation (the owner decides)

**Option A, a switch in each night.** Plain English: the raffle is one on/off fact about a night, and A puts
exactly one switch where the organiser already is, with the reason right under it when it cannot move. It is
the shortest path (3 taps to open), it reads well on the common shape (a few nights, one raffle locked), and
the list line "Raffle &middot; 23 entered" answers "is anyone in?" without opening anything. The switch never
acts alone: both directions go through the confirmation, so the hard stop holds.

**Why B is still a real choice.** B never shows a control that cannot be used: there is always exactly one
button and it says what it does ("Message us to cancel" instead of a greyed switch). Its 4-step track
teaches the life of a raffle (Open, Entries, Closed, Winner) to an organiser running one for the first time,
and the chip on the list is easier to scan at 50+ nights. It costs one more tap and a second sheet.

**Alternatives rejected:** (1) a Raffle tab: the brief keeps the tab bar unchanged, and a raffle without its
night has no meaning; (2) a bulk "raffle on for every Friday" switch: it skips the per-night hard stop and
hides which nights are locked; (3) an inline switch on each list row: one mis-tap away from a hard-stop
action and too small to carry the lock reason.
