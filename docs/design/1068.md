# Design record: P3 W2d sessions and line-up (PR #1068)

Flag: `organiserP3` (OFF). Branch `claude/p3-w2d-sessions-lineup`. Brief: `brief/p3-w2d-sessions-lineup`.

## Brief
- **Who:** an organiser on a phone (390x844), on their P3 event page.
- **One job:** change a session (name, times, room, level, line-up) for every date or for one date, add one, take one off.
- **Feel:** the C3 sheets: one sheet per step, plain words, every greyed control says why.

## Stage 2: matches C3 / does not and why

A stored kind outside them shows pressed and read-only. |

| Scope picker ("Which dates?", `lineupscope` / `sessscope`) | radio of 2 `p3-choice` at the top of the session sheet | Partly | Only "Every date" and "Just <date>" (owner Q1: "From X on" is out). It sits ON the sheet, not as a separate step, so the scope is picked before the edit. |

## Stage 4: contrast, walk
- New CSS (appended to `p3.css`): `.p3-chips` (44px chips; pressed = `--btn`/`--btnfg`, the same pair as the primary button), the picked `p3-choice[aria-checked]` (gold border), `.p3-seg2`, `.p3-btn-sm`, `.p3-pad`. No new colour token. The axe colour-contrast check on every walk state shows 0 violations in light and dark.
- Walk: `docs/handover/p3-w2d-sessions/` (40 PNGs, `metrics.jsonl` 36 rows: all 0 sideways scroll, min tap 44px, 0 clipped, 0 contrast). One red was found and fixed before the final run: the Add buttons were not full width.
