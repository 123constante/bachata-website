## Brief checklist

1. **`redeemAction()` (`joinModel.ts:257-270`)**: every `JoinRedeemOutcome` kind is handled:
   done -> done; not_linked -> stop/not_linked; dead (used/expired/revoked/invalid) -> refetch preview -> dead
   screen; wrong_account (server `email_mismatch`) -> stop/wrong_account; email_unproven -> stop; rate_limited ->
   stop (redeem variant, Try again disabled + home); profile_incomplete -> refetch completion -> About step;
   sign_in -> sign out -> email step; refused (team_full, unconfirmed_account, unknown) -> reason screen;
   failed/network/default -> stop/network (Try again -> `join()`). "Told" copy (`JOIN_COPY.notLinked.body`)
   is rendered only by `StopScreen` case `not_linked`. Every stop screen has at least one live control
   (Try again / Sign out / home link / WhatsApp). OK.
2. **Post-sign-in branch (`JoinPage.tsx:235`)**: now `applyRedeem(await attemptRedeem(token), 'claim')`, the
   same mapping as the Join tap. Double-tap: `verify` and `join` both guard on `busy`, and `attemptRedeem`
   dedupes in-flight calls per token (`joinApi.ts:81-91`), so one redeem per tap. Sign-in return: `clearStep()`
   runs before the redeem, so a stale `?step=code` URL is gone whatever the outcome. Network stop from the
   claim path is tagged `from: 'join'`, so Try again calls `join()` (a fresh redeem), which is the correct retry. OK.
3. **"Send my code"** (`JoinScreens.tsx:115`): disabled only while `busy`. Empty -> page shows `badShape`
   ("Use an email like name@example.com."), and the "Type your email to get a code." line is also on screen;
   bad shape -> `badShape`; non-ASCII -> `notAscii`; valid -> sends. No copy points at a missing control. OK
   (see N2 for the test gap).
4. **Tests really fail on the old behaviour**: yes, by surgical mutation on the PR head (results below).
   One vacuous-ish test name (N2).
5. **Server rules (prod `redeem_organiser_invite_v1`, read-only `pg_get_functiondef`)**: `email_unproven` only
   when the open bound invite matches the caller's address but the session is not a proven mailbox;
   `email_mismatch` (+ `invite_email_hint`) when bound to another address; `not_linked` only for a
   person-bound invite whose link to `person_profile_id` failed (attempt row + audit written, invite open).
   `invalid/used/revoked/expired` -> client `dead`; `team_full`, `unconfirmed_account` -> `refused`;
   `sign_in_required` -> `sign_in`; profile gate exception -> `profile_incomplete`. The client mapping
   matches the server on every reason. OK.

## Findings (ranked)

### N1 (low, pre-existing, now one-line fixable): claim-path success leaves the organiser-home cache stale
- `JoinPage.tsx:197`: `if (from === 'join') void queryClient.invalidateQueries({ queryKey: ORGANISER_HOME_KEY });`
- Scenario: person-bound invite, sign in by code, claim `no_match`, redeem answers `redeemed`. Between
  SIGNED_IN and the redeem's answer, `ownList` (`JoinPage.tsx:77`, enabled when `user && open && !redeemed`,
  `staleTime: 60_000`) can fetch and cache `['organiser-home', userId]` WITHOUT the new seat. The Done
  screen's link goes to the organiser home, whose `useOrganiserChoice` reads that same key and may show the
  pre-seat list for up to 60 s.
- Same as main (the old claim branch did not invalidate either), so not a regression; but the PR built the
  "ONE place" and kept the asymmetry. Fix: drop the `from === 'join'` guard (invalidate on every `done`).
- Not reproduced in a browser (timing-dependent).

### N2 (low, test gap): no page test pins the empty-Send error; the unit test name contradicts its assertion
- `joinOutcomes.table.test.tsx:45` is named "an untouched or malformed tap sends nothing" but asserts
  `onSend` IS called with `''` (correct behaviour, wrong name).
- Mutation D (`JoinPage.tsx` send(): show no error when `reason === 'empty'`) stays **green** (338/338).
  The handover's "tap shows the bad-shape error" is only proven for a malformed address
  (`joinJourney.test.tsx:225`), not for an empty box.
- Fix: rename the test ("an empty tap hands '' up; the page validates") and add a page row: empty Send ->
  `join-email-error` = `JOIN_COPY.email.badShape`, no send call.

### N3 (low, test coverage): the post-sign-in table covers 5 of 10 outcome kinds at page level
- `joinJourney.test.tsx:368` covers email_mismatch, email_unproven, rate_limited, team_full, not_linked.
  `dead`, `failed` (network), `profile_incomplete`, `sign_in` and `done` on the claim path are covered only
  through the pure `redeemAction` table, not through the page (e.g. network on the claim path -> Try again ->
  redeems -> lands correctly). Since both callers share `applyRedeem`, risk is low. Suggest adding `invalid`
  and a thrown-RPC row to the `it.each`.
