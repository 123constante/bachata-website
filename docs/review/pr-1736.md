- [ok, 2] No deadlock. Ruleset required contexts (tests/fixtures/ruleset-main-checks.json = required-jobs.json pr_head) include `e2e-smoke` and `unit (Europe/London, full)`. On a draft, `e2e-smoke` reports skipped (passes). A skipped job counting as success is the reason merging would NOT wait; what holds the merge is draft state plus the missing matrix context `unit (Europe/London, full)`. The same applies to the matrix `phone-qa`: on a draft it reports `phone-qa`, not `phone-qa (1..3)`. Suggest rewording to state those two facts.
- [low, comment wrong] The phone-qa.yml comments say the job "runs ... on every push to main", but phone-qa.yml has no `push` trigger (pull_request + workflow_dispatch only, the same as on main).
- [low, latent race] After ready_for_review, the draft-time skipped `e2e-smoke` / `build-smoke` check-runs on the same SHA count as OK (success|skipped|neutral) until the new runs register. bot-automerge arms auto-merge on that same event, but the missing `unit (Europe/London, full)` (about 8 min) holds GitHub, queue-merge and autopilot (`required-jobs.mjs`: latest run per name, missing = refuse) until well after the fresh runs exist. Safe today only because a matrix context is required. If `unit (Europe/London, full)` ever leaves the required set, a stale skip could satisfy e2e-smoke.
