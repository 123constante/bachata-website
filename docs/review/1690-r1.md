## Findings (nits)

- **N1 (test gap)**, `tests/defectEscape.test.ts:23-27` and `scripts/defect-escape.mjs:48`. No test has a non-fix commit that is NEWER than the fix. Because of that, deleting the `p.ts <= f.ts` ordering guard leaves every test green. Suggested test: `compute([c("fix: x", 3, "src/a"), c("feat: y", 1, "src/b")], NOW).escaped === 0`.
- **N2 (test naming)**, `tests/defectEscape.test.ts:51-56`. The "non-vacuity: a mutated fix parser" test does not mutate anything. It only shows that a `chore:` subject does not count and a `fix:` subject does. The real mutants are caught by other tests (see check 2), so coverage is fine, but the name overstates what the test does.
- **N3 (recipe edge, informational)**, `scripts/defect-escape.mjs:31,42,80`.
  - Because the regex is a prefix match, `Fixture...`/`Fixes...` subjects count as fixes.
  - A commit that touches no files maps to area `other` (line 42), so two file-less commits "share an area".
  - `-n 400` truncates priors if main ever gets more than 400 first-parent commits in 14 days. It is currently about 51 a week, so this is fine for now.
  - All three are frozen-recipe choices. I am recording them, not asking for a change.
