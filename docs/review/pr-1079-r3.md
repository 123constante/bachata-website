## Findings, ranked

**S1 (should-fix, CONFIRMED by render; the position is fix 1's, the height is fix 2's). The toast column covers the open sheet's footer, and an alert's Dismiss sits exactly over the money button.**
`p3.css:256-259` anchors the column at `bottom: tab bar + 12px` with `z-index: 90`, over the scrim (70) and so over the sheet footer, which is sticky at the sheet's bottom (`p3.css:235`). Measured: one alert = 712-768, its Dismiss at x 300-370, y 718-762; under that exact spot is "Refund GBP 24.00" (16-374 x 732-776) in the Refund sheet and "Put on sale" (same rect) in the add sheet (`elementFromPoint` at the Dismiss centre after removing the column: `confirm` / `sell`). Three toasts (588-768) cover the Refund sheet's body text and its confirm; six cover 430-768.
Scenario: Refund A, confirm, Keep the order, tap Refund on B; A is refused late: the alert "Refund for Ana's order did not start. ..." lands with Dismiss over B's "Refund GBP 24.00". The person taps Dismiss; the toast is gone on the first tap, and the second tap of a double tap (phones get these when a UI seems not to respond) lands on B's confirm: B is refunded. A status toast (no Dismiss) covers the confirm for 8 s, which is a nuisance, not a risk. Pre-existing in fix 1 (`.p3-toast-top` had the same bottom and z-index), but fix 2 makes the column taller and keeps it on screen until dismissed, so the overlap is now the common case for the money sheets.
Fix: keep the column off every footer. Simplest: anchor it at the top, `.p3-theme .p3-toast-stack { top: calc(var(--top-h) + 12px); bottom: auto }` (the heads are only 44 px of links). Or render it inside the top layer's sheet above the footer (also closes R6). Pin it in `layout.cascade.test.ts` (`resolve([...], 'bottom')` is `auto` / `top` is set).

**N1 (nit, CONFIRMED by P11). A late edit that renamed the ticket is announced under its OLD name.**
`TypeSheet.tsx:65` `type?.name ?? (form.name.trim() || 'New ticket')`: for an edit the saved form name is ignored. Scenario: edit "Door", rename it "Door renamed", Save changes, Escape; the save lands: toast `"Door": Ticket saved.` while the refreshed list shows "Door renamed", so the toast names a ticket that is no longer on the list. The test pins the old name (`stack.draft.test.tsx:435`). Fix: `form.name.trim() || type?.name || 'New ticket'` (the saved form is what the list will show); flip the assertion.

**N2 (nit). Escape mid-close is a no-op while Close and the scrim still close the layer mid-flight.**
`TypeSheet.tsx:212` swallows Escape while `busy` inside the confirm block; `:210` (Close, scrim) still calls `onClose(true)`, and Escape outside the confirm block closes the layer mid-save. Safe (the landing goes through `landed` either way; P12), but Escape then does nothing with no sign why. r2 offered this or "Escape closes the layer". Either document the no-op in the comment at `:211` or route it: `onEscape={confirmClose ? () => { if (busy) onClose(true); else setConfirmClose(false); } : undefined}`.

**N3 (nit, test scope). Alert keys by id are not pinned.**
Mg (keys by text) stays green. The product is right (P10: the same order refused twice yields two alerts, each with its own Dismiss). Add P10 as a test, or assert the two alerts in P1b have distinct keys via two identical texts.
