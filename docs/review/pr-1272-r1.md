### F1 -- `m.instagram.com` profile links do not move; the brief says they do  (fix before merge, CONFIRMED)

- `src/lib/instagramHandle.ts:69` (`PROFILE_LINK = /^(https?:\/\/)?(www\.)?instagram\.com\/([^/?#]+)/i`) and
  `instagramProfileLinkHandle` at `:101`, which returns null for any host other than `instagram.com` / `www.instagram.com`.
- Brief `instagram-refusal-r2.md` line 33: "Website value is an instagram.com PROFILE link (host instagram.com, www., m.; ...)
  AND Instagram box empty -> move". The PR pins the opposite:
  `src/modules/dancer-app/screens/edit/__tests__/instagramInWebsite.test.tsx:33`
  `['m. link (not a profile link by the field rule: stays)', 'https://m.instagram.com/simon.bachata', 'stay']`.
- Failing input: stored Instagram empty, Website typed `https://m.instagram.com/simon.bachata`, Save.
  `websiteInstagramMove` -> `none`; the website rule accepts any https URL, so the delta is
  `{website_url: 'https://m.instagram.com/simon.bachata'}`; Instagram stays empty, the checklist row
  "Your Instagram" stays, and no note under Website says why (the Instagram box itself would have refused
  it with the owner's invalid wording). Mobile share sheets produce `m.` links, so this is the phone shape.
- The PR body's "N1 narrowed" paragraph discloses the bare-word / `simonbachata.com` narrowing but not this one,
  so the owner has not seen the deviation. Either widen the move rule to accept `m.` (one `(www\.|m\.)?` in
  PROFILE_LINK, and let `checkInstagramField` keep refusing it in the Instagram box if that is wanted), or record
  the deviation as an owner decision in the PR body. The brief's test table (line 35) names `m.` as a moving row.
