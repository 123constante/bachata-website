# Review: PR #1165, round 1 (independent)

PR: `claude/tickets-retire-old-screens` @ `ea1c61d`, judged against `main` @ `a1d0fa6`
(which is the PR's merge base). Read-only review: I did not build it, did not push to it, and
did not approve or merge it.

Method: I read the full diff. I grepped for importers of every deleted file. I rendered
`LegacyTicketsRedirect` in a `MemoryRouter` (react-router 7.18.4) with 11 URL shapes. I ran
the PR's tests (11 files, 1233 tests, all green). I applied 7 mutations and reverted each one.
Probe and mutation files were scratch only and were never committed.

## Findings (most severe first)

### F1. No test sees the component pass the query string to the redirect. Dropping it ships green and breaks Stripe returns. Fix before merge. CONFIRMED

- `src/modules/organiser/tickets/LegacyTicketsRedirect.tsx:7`
- What is wrong: the matrix test (`legacyRedirect.matrix.test.ts`) only covers the pure
  function `legacyTicketsTarget`. Nothing renders the component or the route. The step this
  PR exists to protect, forwarding `?o=&stripe=` from the URL into the function, has no test.
- Mutation **M5**: change `legacyTicketsTarget(pathname, search)` to
  `legacyTicketsTarget(pathname, '')`. Result: `src/modules/organiser/tickets` +
  `p3/tickets`: **1223/1223 pass**.
- Failing input under M5: `/account/tickets?o=org1&stripe=return`, the URL Stripe sends the
  person back to. It lands on `/account/p3/you/get-paid` with both `o` and `stripe` lost.
  Get paid then shows no back note (`tix-getpaid-back`) and does not invalidate
  `ticketKeys.stripe(org.id)`, so a just-finished onboarding can still show as "not
  connected". `payingOrganiser` may also pick a different page than the one that onboarded.
- Fix: add one jsdom test that renders `<MemoryRouter initialEntries={[url]}>` with the real
  route element and asserts the final location for at least the two Stripe rows and one
  event row. My scratch probe did exactly this and passed on the PR head, so the test is
  cheap.

### F2. Dropping `replace` from the redirect is not caught. Fix before merge. CONFIRMED

- `src/modules/organiser/tickets/LegacyTicketsRedirect.tsx:7`
- Mutation **M6**: change `<Navigate ... replace />` to `<Navigate ... />`. Result: **1223/1223
  pass**.
- Failing input under M6: open `/account/tickets?o=org1&stripe=return` (Stripe return), then
  press Back on Get paid. The browser returns to `/account/tickets…`, which redirects forward
  again. The person cannot go back past it. The code is correct today; this is a test gap on
  the redirect-loop guard. The same render test as F1 can assert `history.length`, or that
  `navigate(-1)` leaves the `/account/tickets` entry.

### F3. With `organiserTicketing` ON and `organiserP3` OFF, organisers who had ticketing on main now get NotFound. Fix before merge, or record the owner's decision. PLAUSIBLE (depends on the live Vercel env)

- `src/components/AnimatedRoutes.tsx:272`
- On main, `/account/tickets/*` mounted on `organiserTicketing && organiserSelfServe`, and
  the old screens were the whole ticketing UI. P3's ticketing screens need `organiserP3`. The
  PR deletes the old screens and adds `organiserP3` to the gate.
- Failing input: env with `VITE_ENABLE_ORGANISER_TICKETING=true`,
  `VITE_ENABLE_ORGANISER_SELF_SERVE=true`, and `VITE_ENABLE_ORGANISER_P3` unset.
  `/account/tickets?o=org1&stripe=return` (a live Stripe account link minted before the
  merge) gives the site NotFound. On main it gave the Tickets home. In that env the
  organiser has no ticket management screen at all: nothing to set up, sell or refund.
- Not a problem if prod runs both flags on or both off. Both default OFF in code. I could not
  read the Vercel env, which is why this is PLAUSIBLE. The gate itself is internally
  consistent: it points only at targets that exist, so there is no loop and no redirect to a
  404. Ask: confirm the prod and preview flag values in the PR body. If any environment has
  ticketing on and P3 off, turn P3 on (or ticketing off) before merging.

### F4. An uppercase `/EVENTS/` segment now goes to Get paid, not the event page. Nit. CONFIRMED

- `src/modules/organiser/tickets/legacyRedirect.ts:15`
- React Router matches case-insensitively, so on main `/account/tickets/EVENTS/s1` matched
  `events/:seriesId` and opened that event's tickets. The new regex `/^\/events\/…/` is
  case-sensitive.
- Failing input: `/account/tickets/EVENTS/s1` goes to `/account/p3/you/get-paid` (probed).
  An uppercase base works (`/ACCOUNT/TICKETS?o=org1&stripe=return` gives Get paid with both
  params), because the code slices by length. Fix: add the `i` flag to the regex, plus one
  matrix row. This is also **the URL the matrix misses**. A second one:
  `/account/tickets//events/s1` (double slash) goes to Get paid.

### F5. `?stripe=return` with no `o` drops `stripe`. Nit. CONFIRMED

- `src/modules/organiser/tickets/legacyRedirect.ts:20`
- Failing input: `/account/tickets?stripe=return` gives `/account/p3/you/get-paid`. No back
  note and no Stripe cache refresh. The matrix pins this on purpose (row 8). The old
  `stripeBack` always minted `o`, so real Stripe links are not affected. The only way to hit
  it is a hand-edited URL. Mixed-case keys (`?O=..&STRIPE=..`) and an empty `o=` are dropped
  the same way, also only by hand-editing.

### F6. Pre-existing, outside this diff: `RefundSheet.go()` has no re-entry guard. Nit, not introduced here. PLAUSIBLE

- `src/modules/organiser/p3/tickets/RefundSheet.tsx:43`
- `go()` relies on `disabled={busy}`, which only applies after a re-render, so two clicks in
  the same frame could send two `ticket-refund` calls. This PR only swapped `p3Reason` for
  `reasonMessage` on line 53. The double-submit guard is the same on main. The server's
  refund path probably dedupes (not verified). A one-line `if (busy) return` would close it.
  Not a merge blocker for this PR.

## What I checked and found clean

1. **Old URL shapes (probed in a real router):** these all land correctly, with no loop:
   - `/account/tickets?o=org1&stripe=return`, `/account/tickets?o=org1&stripe=refresh`, and
     the trailing-slash, reordered-params and `%20` variants go to `…/you/get-paid` with
     `o` and `stripe` kept.
   - `/account/tickets/events/s1[/]?o=…` and `/account/Tickets/events/s1` go to
     `/account/p3/events/s1`.
   - `/events/a%2Fb` stays one encoded segment.
   - A `#hash` is dropped, which is harmless.
   - Unknown sub-paths go to Get paid keeping `o`.

   Dropping `o` on the event redirect is fine: `EventPage` reads the series by id through
   `useP3Home` and does not use `o`.

   **No open redirect:** every target is built from `P3_PATHS` or `P3_TICKET_PATHS` with a
   fixed `/account/p3` prefix. The decoded id is re-encoded with `encodeURIComponent`, so
   `%2F`, `..` and `//host` cannot leave `/account/p3`.

   **No loop:** the targets are `you/get-paid` (mounted by `youGetPaidRoute` on
   `organiserTicketing`) and `events/:seriesId` (mounted by P3). Both exist exactly when the
   redirect route is mounted. P3's own `*` goes to P3 home, never back to `/account/tickets`.
2. **Stale importers:** I grepped every deleted file (`TicketRoutes`, `TicketsHome`,
   `SeriesTickets`, `TypeSheet`, `RefundSheet`, `parts`, `paths` under
   `organiser/tickets/`, plus `TICKET_PATHS` and `TICKETS_BASE`). There are no importers
   left in `src`, `scripts`, `tests`, `e2e` or `.github`. The `./parts` and `./paths` hits
   all belong to other modules. Nothing on main linked to `/account/tickets` from outside
   the deleted screens. `tsc -p tsconfig.app.json` reports no errors in any touched file;
   the 126 errors it does report are in unrelated files.
3. **featureFlags.ts:** this is a comment-only change.
   - OFF: there is no `/account/tickets` route, so it gives NotFound, the same as main.
   - ON with P3 on: the redirect is mounted.
   - ON with P3 off: see F3.
4. **P3 screens** (`GetPaid`, `RefundSheet`, `TicketsEntry`, `TypeSheet`, `data.ts`,
   `model.ts`): this is a pure rename. `p3Reason` became `reasonMessage` and `p3MoveBlock`
   became `moveBlock`. The words do not change, because `PAYMENTS_WHERE` (now in
   `ticketModel.ts`) is the exact string `p3Words` used to swap in.
   - `moveBlock`, `reasonMessage` and `PAYMENTS_WHERE` have no callers outside `p3/tickets`
     (grepped), so no other screen's copy changed.
   - Empty and error states are untouched.
   - `tickets.matrix.test.tsx:108` still asserts that no rendered text names the "Tickets
     home".
5. **AnimatedRoutes / catchallClientPaths:** `'/account/tickets/*'` stays in
   `CATCHALL_CLIENT_PATHS`, so the server still serves the SPA. No route that existed on main
   is removed except the old area itself; see F3 for the flag combination where that
   matters.
6. **Mutations:**

   | **M2** | event goes to `eventDetails` (the wrong page) | 4 failed |
