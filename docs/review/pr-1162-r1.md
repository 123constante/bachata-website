### F2 -- src/lib/accountRouting.ts:274 -- "find or create your page" shown when the person already has a page (P3 Review return)
**Severity: fix before merge (the CLAUDE.md copy rule says a label must never point at a screen that isn't there). CONFIRMED (probe test).**

The match strips the query, so every `/account/p3/start?...` end gets the label. One real caller sends someone who already has a page to that path. In `src/modules/organiser/p3/onboarding/OnboardingFlow.tsx:267`, the Review row for an unfinished dancer profile navigates to `finishProfileHref('/account/p3/start?o=<orgId>&at=review')`.

Failing input, traced with a temporary vitest probe (not committed):
- `finishProfileHref('/account/p3/start?o=abc&at=review')` gives `/finish-profile?returnTo=%2Faccount%2Fp3%2Fstart%3Fo%3Dabc%26at%3Dreview`.
- `oldDancerHomeRedirect({allowed:true, view:'finish', profile:'incomplete', returnTo:<that>})` gives `/app/welcome?returnTo=...` (an explicit returnTo wins).
- `onboardingEndLabel(onboardingEnd(<that>))` gives **"Next: find or create your page"**. The button then lands on the Review step of a page the person already found or created.

The new test row `['P3 start with query', `${START}?o=abc`, ...]` locks this behaviour in, where it should flag it.
Suggested fix: when `o=` is present, use a page-specific label (for example "Next: back to your page"). Or label only the bare start path with "find or create" and add a test row for `?o=..&at=review`.

### F3 -- src/lib/accountRouting.ts:274 -- exact match only; a trailing slash falls through to "Continue"
**Severity: nit. CONFIRMED (probe), low reachability.**
