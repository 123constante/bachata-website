## Verdict: BLOCK (one-line copy fix, then PASS WITH NITS)

The gate wiring (F-10, organisers half) is correct and well tested. F-46 shows the right
rows to the right person, but its "what you can do" line names a control that does not exist
on P3 (F1). CLAUDE.md's definition of done forbids that ("No copy that points at a control that
is not on screen"), and the brief asks about it directly. The fix is to change the wording.
Everything else is a nit or a test gap.

## Findings

### F1 (BLOCK): Welcome tells a declined person to "ask again with a note", but P3 has no note field
- `src/modules/organiser/home/onboarding/onboardingModel.ts:63` `DECLINED_NEXT = 'You can ask again with a note, ...'`
  (the comment above it at :58 says "Names only controls on that screen").
- P3's ask sends an empty message: `src/modules/organiser/p3/onboarding/pageApi.ts:123`
  `requestOrganiserAccess(id, '')`. `ClaimSheet` (`OnboardingFlow.tsx:790+`) has no input or textarea. There is nowhere to type a note.
- Failing scenario: a person is declined, opens P3 Welcome, reads "ask again with a note", taps
  Find your page, picks the page and gets a claim sheet with only an Ask button. The copy promises a control that is not there.
- Fix: say "You can ask again, or create a page of your own. Both start from Find your page." Or add a note field to ClaimSheet (that is a scope decision for the owner).
  The test at `welcomeDeclined.matrix.test.tsx:91-94` checks only that "Find your page" exists. It cannot catch this.

### F2 (nit, test gap): the date in the declined line is checked against the function under test
- `welcomeDeclined.matrix.test.tsx:87` expects `rows[0]` to contain `declinedLine(...)`, which
  is the same function the screen calls. Mutant M6 (drop the ` on <date>` part of `declinedLine`)
  **survives**: the screen and the expectation change together. F-46 requires the date.
- Fix: assert a literal, e.g. `/said no on \w+day \d+ \w+\./`, or a fixed `now` and an exact string.

### F3 (nit, test gap): the 30-day boundary is not pinned
- `CASES` (test :63-73) uses declines answered 2, 4 and 59 days ago. Mutants `DECLINED_VISIBLE_DAYS = 45`
  and `= 7` both **survive** (`= 90` and `= 2` are killed). Add rows at 29 and 31 days answered.

### F4 (nit, test gap): the `decision_note` mapping in `fetchMyAccessRequests` is untested
- `selfServeApi.ts:102`. The matrix injects `decisionNote` straight into `reads.requests`, which skips the
  mapper. Mutant M3a (`decisionNote: null`) **survives** across all 100 organiser test files.
  Prod does return `decision_note` (see Data shapes), so this mapper is the only link. Add a
  mapper unit test: string, then whitespace-only gives null, then missing gives null.

### F5 (nit, test gap): `!orgId &&` guard on the declined card is untested
- `OnboardingFlow.tsx:592`. Mutant M5 (drop `!orgId &&`) **survives**. Prod has one person with a
  granted request plus a declined one on another page (shape below). That person has a page, so the card
  is hidden by design. No test pins it. Add a case with an `orgId` set (a granted page) and a decline, expecting no card.

### F6 (nit, stale comment): `accessRequestModel.ts:13-17` says the decision note is not readable
- It says "The admin's reason is NOT here ... returns the requester's own message, not the decision note".
  Prod's `list_organiser_access_requests_v1('mine')` now returns `decision_note` (only for
  `status='declined'`, scoped `q.user_id = auth.uid()`). The comment contradicts the PR. Update it.
  R1's `OnboardingView.tsx:246` still says "The reason is not shown here yet". That is R1's own copy and was left alone on purpose, but it is now out of date too.

### F7 (nit): the new test file adds three `tsc` errors
- `welcomeDeclined.matrix.test.tsx:32` uses `PAGES` (undefined) and `:40` uses `opts.askFailX` (not in the type).
  Main has 119 `tsc -p tsconfig.app.json` errors and the PR has 122: these three are new, and the only new ones
  (`OnboardingFlow.tsx:315` is inherited from main, where it is at :314). No CI job runs `tsc` (`typecheck.yml` runs
  `check:rpc-typing` and `check:wallclock-brand` only), so this does not go red. `PAGES` would throw a ReferenceError if a case ever
  reached the Find step. Remove both leftovers.

### F8 (nit): the F-10 screen-level test is a source regex
- `gate.matrix.test.tsx:333-337` greps `SeriesOrganisers.tsx`. The behaviour test (`OrganisersHarness`)
  drives `useEventSend` with the hook, not the real screen. M1 is killed only by the regex. That is acceptable and matches
  the file's existing "seven write screens use the gate hook" pattern, but a rename of `kind`
  would fail a correct refactor.

## Q1: does the diff meet F-10 and F-46?
- **F-10 (organisers half): yes.** On P3 (`kind === 'p3'`), `useEventSend` passes `gated`.
  `useFlowSend.send` calls `gated(err, copy)`, which opens the sheet and returns null for `onboarding_incomplete`, so `StepError`
  shows nothing. Every other refusal keeps its wording through `copy`. `run`'s catch is gated the same way.
  The route sits under `<P3Shell>` (`P3Routes.tsx:70,78`), which mounts `<GateHost />` (`P3Shell.tsx:71`), so the sheet has a host.
  The create-first-event half (NewFlow, useNewSend) is outside this PR, as the brief says.
- **F-46: partly.** The card shows the date, the page name (or "An organiser"), the answerer's note when there is one,
  and next steps. The next-steps line is wrong (F1). Wrong-person exposure: **none**. The note comes from the
  `'mine'` scope, which filters `q.user_id = v_user` server-side and returns a note only on declined rows. The client never sees another
  person's request.
- Every state says what the person can do: declined (yes, apart from F1); none, read failed and older than 30 days show no card, and
  Welcome's normal "Find your page" CTA stays.
