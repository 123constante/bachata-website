## Verdict: PASS with should-fix

The re-skin itself is sound: the `OrgSurface` context defaults to R1's exact values, so `/account/o` keeps the old
behaviour with the flag off, every P3 difference is gated on `surface.kind === 'p3'`, and the fix-2 claims hold
(section 4). What the live RPC bodies show (section 1) is that the Team screen this PR re-homes offers three
controls the server refuses, and that prod's majority shape (a page with ONE manager and NO owner: 39 of 51
pages) is the one the matrix does not have. None of that is new code in this PR, but the brief's rule is "the UI
never offers what the RPC refuses", so F1-F3 are should-fix before P3 Team reaches real managers; the owner may
treat F1 as blocking since both open join requests on prod sit on exactly that shape.
