## Findings

**N1 (perf, small fix).** Every upcoming ticket starts with its QR open (`open = !past`), and each open card builds its QR in `useMemo` on mount. The RPC returns up to 500 tickets; a buyer with a few dozen upcoming tickets draws a few dozen QR codes at once on a phone. The matrix tests at most 3. Suggest: open by default only the first 3 upcoming cards (or only the ones dated today), the rest "Show QR code". Add a 40-ticket row asserting the count of `ticket-qr` nodes.

**N2 (test gap, tiny).** No row for a past ticket that is also checked in (the "Show anyway" path sets `open` as well, which I read as correct). Add one row.
