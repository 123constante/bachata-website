### 2. `.data` twin warm

- `app/cloudflarePurge.ts:135` adds `warmDataTwin: true` to the `event-<id>`
  rule only; `:280` `if (rule.warmDataTwin) warm.add(`${base}/${slug ?? id}.data`)`.
  Canonical slug (or uuid when the resolver has none), origin prefixed at
  `:295`, no query string. Mutant M12 (add `?v=1`) fails 6 tests.
- Festival rule (`:136`) unchanged, `/festival/<slug>.data` still not warmed
  (M13 fails 1 test). BUT the festival planner rows did change
  (`app/cloudflarePurge.test.ts:191`): a festival purge now also warms
  `/event/<slug>.data`, because `purgeTagsFor("festival")` includes
  `eventTag(id)` (`app/cacheTags.ts:172`) and the festival page stamps it
  (`app/cacheTags.ts:86`). That is one more render per festival write, correct
  by design, and the PR body states it only indirectly. See F4.
- Hidden path warming a `.data` 404 (`cloudflarePurge.test.ts:239`): a thrown
  404 carries no `Vercel-Cache-Tag`, so `cacheHeaders` returns only
  `public, max-age=0, must-revalidate` (`app/detailLoader.ts:131-133`); Vercel
  does not store it and Cloudflare, respecting origin headers, should not either.
  Even if Cloudflare's rule did store a 404 for its default 4xx TTL, the
  un-hide write fires the same two-pass purge of the same URLs. Harm: one
  uncached SSR render per hidden write. Accepted. See F5.

## Findings (ranked)

**F1. `real-data-verified` is red: the Verified block is not in the parser's shape.**
`scripts/check-pr-real-data-verified.mjs:42-50` wants three list lines
`- Shapes surveyed: <text>`, `- Checks run: <text>`, `- NOT verified: <text>`
under `## Verified on real data`. The body uses bold labels with a suffix
(`**Shapes surveyed (read-only):**`), leaves `Checks run:` and `NOT verified:`
empty after the colon with the content in sub-bullets. Job 125086872524 log:
"Shapes surveyed: line is missing / Checks run: empty after the colon /
NOT verified: empty after the colon"; `mergeable_state: blocked`.
Failure scenario: nobody can merge; a reader who trusts the PR's own CI table
("real-data-verified" is not in it) misses that the gate rejected it.
Fix: edit the PR description only (one summary sentence after each colon, keep
the detail as sub-bullets below). No commit needed.

**F2. Untested body shape: explicit `tags` + `entityType`/`entityId` + `stateChange: true`.**
Mutant M11 (drop `!explicitTags?.length` from `isEventWrite`,
`api.revalidate.tsx:134`) keeps all 96 tests green. The existing row
`:141-146` sends `tags` without an entity, so `entityType` is undefined and
the guard is never what stops it. Failure scenario if the guard is lost later:
a manual/bulk purge that also names an event runs the visibility lookup and,
when the event is hidden, hard-deletes the WHOLE explicit list (the 11-cold-render
case the brief forbids). Nit: add one row
`{ tags: [EVT, "seo-landing"], entityType: "event", entityId: EV, stateChange: true }`
asserting soft full list, no hard delete, `resolvePublicEventRef` not called.

**F3. `!hidden` in the `stateChange` expression is dead code (`:139`).**
`if (hidden)` at `:152` is evaluated first, so M5 is an equivalent mutant.
Harmless; it reads as documentation. Keep or drop, no test can pin it.

**F4. Festival writes now warm `/event/<slug>.data` too.** `cloudflarePurge.test.ts:191`
changed (the brief said "no change to festival rows"). It follows from
`purgeTagsFor("festival")` carrying `eventTag(id)`, and the festival page is
tagged with it (`cacheTags.ts:86`), so the extra render is the right one. The PR
body says only that `/festival/<slug>.data` is not warmed; say the `/event`
twin IS warmed on festival writes so the per-write render count is honest
(festival: 5 warms, was 4). Docs nit.

**F5. Hidden path warms a `.data` 404.** One uncached SSR render per hidden

the un-hide purge covers any 4xx Cloudflare might hold. Accepted, as the
