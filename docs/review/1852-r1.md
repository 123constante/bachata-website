1. Scope: test-only. `tests/routeRunner.test.ts` plus one handover doc `docs/briefs/flake-routerunner-hooks-handover.md`. No app code, no CI config, no migrations.
2. No retry, skip, `.only` or deleted assertion. The old `status === 0` and `PASS n cases` assertions are kept (`r.code` / `r.stdout`) and one is added (`r.how === 'exited'`). The `it.skipIf` guard is unchanged from main. The flat 60 s cap is replaced by a 30 s no-output stall watchdog plus a 180 s ceiling. That is not a blanket timeout bump: a hang (no output) still fails in 30 s.
3. Root cause matches the diff. The script prints one `ok`/`FAIL` line per case, and its wall time follows CPU load, so a wall-clock cap measures load, not hangs. Resetting the watchdog on each output line removes that race.
4. Watchdog: spawned `detached: true` (own process group). `finish()` sends SIGKILL to `-pid` on stall, on ceiling and also on a normal exit, and ignores only ESRCH. It resolves once, guarded by `done`. A hang or an endless loop resolves `how = 'stalled'|'ceiling'`, so `expect(r.how).toBe('exited')` fails. It cannot pass on a hang.
   Probe (copy of the PR's logic, 1.5 s limits): a script printing once then blocking on `sleep` returned `stalled`; a script printing forever returned `ceiling`; `pgrep` found no leftover `sleep` in either case.
5. `npx vitest run tests/routeRunner.test.ts` on the PR head: PASS, 96/96. The shell test ran (not skipped): 22.1 s on its own, 26 s for the file.

## Findings
- nit tests/routeRunner.test.ts:218 `stderr` is piped but never read. If the script ever wrote more than about 64 KB to stderr, it would block and fail as `stalled`. That is a false red, never a false green. `stdio: ['ignore', 'pipe', 'ignore']`, or draining stderr, would close it.
- nit tests/routeRunner.test.ts:229 The process-group kill does not reach the `setsid -w` lock holder in `docs/ci-offload/acer-web/gate-job-started.sh:360`. It runs in its own session. It is bounded by `HOLDER_MAX_S` and its watched pid, and the old `spawnSync` did not reach it either, so this is not a regression.
- nit tests/routeRunner.test.ts:239 On failure, the assertion shows only `how`. Adding the last stdout line to the message would make a stall easier to diagnose from CI logs.
