## Check 4: the three judgement calls

**(a) Cover "Go live" with profile questions left -> P3 event page (`NewFlow.tsx:326-330`).** S1, should-fix. In R1 the same tap lands on "Almost live", which asks the questions and finishes. In P3 it `navigate(paths.event(seriesId))` with no router state: the event page's toast reads `location.state.p3Toast` (`p3/screens/savedToast.ts:13`), so nothing is shown; the Status sheet's "Put it live" row knows three reasons only (no coming date, no cover, no session; `p3/data/eventPage.ts:61`), none of them "finish your page", so the row renders enabled and the tap is refused by the server with its own words. Failure scenario: new organiser, page onboarding not finished, uploads a cover and taps "Go live": the screen changes to an event page with a Draft tag and no explanation; tapping "Put it live" there errors. Fix in the round: carry words (`{ state: { p3Toast: ... } }`) or, better, go to P3's own Review for the page, `p3StartReview(selected.id)` (`p3/shell/paths.ts:61-62`, where Home's Continue and the editor's "To finish" line already go). Also untested (M4 survived).

**(b) Help rows change/add/cancel -> P3 Events (`surface.tsx:74-76`).** Sound: P3 has no standalone date flows (they are sheets on the event page), and Events is the screen that opens them. Pinned (M7 red). N1: "Change a date" landing on a list is a two-step the row label does not promise; acceptable for now.

**(c) Done after New event: back = the new event (`NewFlow.tsx:295,322,339`; `doneState.ts:39`).** Sound and consistent with W4a (primary "Back to <event name>", secondary "Back to You", `Done.tsx:71-81`); `sanitizeReturnTo` accepts the `/account/p3/...` path (`lib/authRouting.ts:8-31`). But it is the untested half of S2: with `doneBack = null` (M3) Done shows only "Back to You", and with the regex reverted (M10) the primary says the generic "Go back" instead of the event's name; both mutants survived.
