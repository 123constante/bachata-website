## Open (non-blocking)

- **O1** The `Done` button in `PicturesSheet` (`DetailsScreen.tsx:~232`) is not disabled while `uploading`. If the owner taps Done mid-upload and then Save, the save sends the list without the in-flight picture and `back()` navigates away. The upload then lands on an unmounted form: the picture is uploaded but never saved, with no message. Fix: `disabled={uploading}` on Done (and Close), or hold the tray save while uploading.
- **O2** (pre-existing, server and old area) A festival `default_gallery` is still owner-writable through `apply_aggregate_write_p5` (no festival refusal for that key) and the old area editor. The P3 copy says the team sets it. Queue for the admin repo (CONTRACT) if festival media is meant to be admin-only.
- **O3** Test gaps in the PR. There is no case for: (a) ended/archived lock, (b) gallery + another field in one save, (c) an upload failing mid-batch, (d) the cap slice on add. All four pass in this reviewer's scratch tests (above). Worth adding to `seriesGallery.matrix.test.tsx`. Also rename "not the owner (profile unfinished)" to say profile-unfinished.
- **O4** `detailsPlan` sends `draft.name.trim()` and `mediaCommand` sends `ws.series.name`. They only differ if a stored name has spaces around it, which is harmless (the name is required anyway). The deep-equal test would not catch that shape.
