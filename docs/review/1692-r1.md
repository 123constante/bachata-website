## Brief checklist

1. **Fail closed.** Pass. `decideUnitStamp` (`scripts/lib/unit-stamp.mjs:13-28`) returns run for a missing, non-string, unparseable, wrong-shape, other-tree, future, or >= 60 min stamp. The CLI catches every throw and prints `run` (`scripts/unit-stamp.mjs:20-27,30-35`). The hook defaults to `run` when node is missing or exits non-zero (`.githooks/pre-push:144`). Flipping the decision kills the test (see mutants).
2. **Keyed by tree.** Pass. The stamp holds `HEAD^{tree}`. The hook only honours it when `$unscoped` is empty (`.githooks/pre-push:145`), which means every non-tag, non-deletion ref being pushed is HEAD, so the pushed tree is `HEAD^{tree}`. A new commit changes the tree, so the gate runs. A dirty tree at write time means no stamp (`scripts/unit-stamp.mjs:14`). A dirty tree at push time does not matter, because the push sends the commit, not the working tree.
3. **Stamp location and when it is written.** Partly fails. It lives under `git rev-parse --git-path` (per worktree, inside `.git/`, so it can't be committed), and pre-ship writes it only after `runCheck("test:unit")` returned true. A `CHECK_SKIPS` skip `continue`s before that point (`scripts/pre-ship.mjs:1405-1409,1426-1436`). **But** the CLI also exposes `write` with no test run at all (finding 1).
4. **Other gates intact.** Pass. The skip only sets `unit_where="stamp"`. Section 2, the review-receipt gate, the deletion triage and the unscoped-ref refusal are untouched. No new env var. `test:unit` is a superset of `test:unit:offline` (`package.json:98-99`), so the stamp is never weaker than the gate it replaces.
5. **Windows / Git Bash.** Pass by reading the code; **not verified on Windows**. `execFileSync("git")` resolves `git.exe` from PATH. `--git-path` returns a cwd-relative forward-slash path that Node's fs accepts. `console.log` prints `\n`, not `\r\n`, so `${stamp_verdict%% *}` and `set --` split cleanly. `.gitattributes` keeps `.githooks/*` and `scripts/**/*.mjs` LF, and the stamp is JSON, which doesn't care about line endings.
6. The test runs green (above).

## Findings

1. **REQUIRED: `node scripts/unit-stamp.mjs write` stamps a tree without running any test.** `scripts/unit-stamp.mjs:3,32` (dispatch), plus the `writeStamp` export at `:12`. Anyone, or any agent told never to use `--no-verify`, can run it on a clean tree. The next push then skips the unit gate and prints `pre-ship passed on this exact tree` (`.githooks/pre-push:147`), which is false. That is a quieter `--no-verify` that looks sanctioned, and it breaks brief item 3 ("writes only after test:unit actually passed"). CI's full suite is still the merge backstop, but the local gate's claim becomes untrue. Fix: drop the `write` branch from the CLI so the entry point only does `check`. pre-ship already imports `writeStamp` directly, so the CLI never needed `write`. Update the header comment to match.
2. **Nit: there is a race between the test run and the stamp's tree.** `scripts/pre-ship.mjs:1426-1431` and `scripts/unit-stamp.mjs:14-15`. Both the tree and the cleanliness check are read AFTER the suite finishes. Suppose the tree is dirty when the run starts, gets committed while the run is going (vitest takes minutes), and is clean afterwards. The stamp then records a tree whose committed content is not what the suite ran on. Fix: read `HEAD^{tree}` and the clean status before `runCheck`, and write only if both are unchanged afterwards.
3. **Nit: a tag-only push can skip based on HEAD.** `.githooks/pre-push:93-95,145`. `refs/tags/*` lines `continue` before the unscoped check, so `git push origin v1` with v1 somewhere else still matches HEAD's stamp. This is not a regression: before the PR, that push already ran the local gate against HEAD and the working tree, not the tag. Recorded for completeness only.
4. **Nit: the `Number.isFinite` guard is untested.** `scripts/lib/unit-stamp.mjs:23`. Deleting the line survives the suite. From stamp data it is close to an equivalent mutant: JSON `1e999` parses to Infinity, and the age check then still returns run. With `nowMs = NaN`, though, both comparisons are false and the function returns **skip**. Production passes `Date.now()`, so this can't happen there, but one assertion would pin it: `decideUnitStamp(formatStamp(TREE, NOW), TREE, NaN).skip === false`.
5. **Nit: the test covers only the pure function.** `tests/unitStamp.test.ts` exercises `decideUnitStamp`. Nothing tests the CLI (dirty-tree refusal, throw gives `run`) or the hook wiring (the `-z "$unscoped"` condition). The throwaway-repo walk above showed they work today, but nothing pins them.
