## Verdict: PASS WITH NITS

The PR does what it claims. On `main` the seven (now eight) P3 specs sat in a step that never set their flags, so the gate ran none of them; on this head they run in their own step with the flags on, and the e2e-smoke job on `0ed11b2` reports **86 passed, 0 skipped** for `test:e2e:p3` (job 124585560985) while the legacy step still passes flags-off. The spec lists are a clean partition of main's list. The guard is red on main's shape and green here, its 27-case self-test passes, and 12 of 16 mutants I applied by hand turn it red (the four survivors are below: two are equivalent mutants, two are untested arms).

The guard CAN fail open, in three ways that are not in the PR's "named gaps" list, and the first one is the very failure class it exists to catch: a new P3 walk spec whose source does not happen to contain the literal `VITE_ENABLE_ORGANISER_P3` or `organiserP3` is invisible to it, so it can sit in `test:e2e` and skip forever exactly as the seven did before #1208. None of the findings makes this PR worse than `main`; each is a small, scoped fix. F1 is the one I would land before merge if the guard is meant to meet its own header comment.

## Findings

### F1. A P3 spec is detected by a literal token, so the original defect can recur unseen (fail-open)

`scripts/check-p3-specs-not-skipped.mjs:169` (`const isP3 = /VITE_ENABLE_ORGANISER_P3|organiserP3/.test(source)`). A gate spec that does not contain either string is `{ isP3: false }` and is never checked for flags or skips.

Failing scenario (run against `runCheck` with fixtures; exit **0**): a new spec `tests/e2e/walk-p3-w5.spec.ts` with
`await page.goto('/account/p3'); const mounted = await page.getByTestId('p3-shell').waitFor().then(() => true, () => false); test.skip(!mounted, 'P3 not mounted');`
is added to **`test:e2e`** (the flags-off step), by habit or by a merge like the one this PR already resolved for `walk-p3-create-kinds`. It skips on every CI run, the step is green, the guard says PASS. That is #1208 F4 again. The existing eight specs only trip the detector because their skip MESSAGE says `organiserP3` or because this PR added a `process.env.VITE_ENABLE_ORGANISER_P3` read to them.

Also: the self-test never exercises the `organiserP3` arm (mutant M13 below). Fix (small): classify as P3 any spec named in a `test:e2e:p3*` script regardless of content, and any gate spec whose source navigates to `/account/p3` (`'/account/p3` literal), then add a self-test case for each arm (a spec with no flag token in `test:e2e` that reads `/account/p3` -> 1).

### F2. `test.fail(!mounted, ...)` turns a broken page into an expected failure (fail-open)

`scripts/check-p3-specs-not-skipped.mjs:59` (`SKIP_RE` matches `skip|fixme` only). Playwright's `test.fail(condition, description)` marks the test "expected to fail" when the condition is true; the test still runs, its assertions fail, and the run is reported green ("expected failure"). With the P3 flag on and `/account/p3` not mounting, `test.fail(!mounted)` is a skip with a different name.

Failing scenario (fixture, exit **0**): a P3 spec with `const mounted = await probe(page); test.fail(!mounted, 'not mounted'); await expect(page.getByTestId('x')).toBeVisible();`. The page breaks, the test fails, CI is green, the guard passes. Fix: add `fail` to `SKIP_RE` and hold it to the same gated-conjunct rule (a `test.fail` conditioned on anything but the flags is a violation), plus one self-test case.

### F3. `test.step.skip('walk', body)` hides the whole walk inside a passing test (fail-open)

Same regex, line 59. Playwright 1.63 (the installed version; `step.skip = this._step.bind(this, "skip")` in `node_modules/playwright/lib/common/index.js`) offers `test.step.skip(title, body)`: the step body is not run, the test passes. Wrapping the walk in a skipped step is a green test that does nothing, and the guard does not see `test.step.skip(` because `step` is not in the alternation.

Failing scenario (fixture, exit **0**): `await test.step.skip('walk', async () => { await expect(page.getByTestId('x')).toBeVisible(); });` in a P3 spec, flags on. Fix: match `test.step.skip` and treat it as an unconditional skip (it takes no condition, so it is always a violation in a P3 spec).

### F4. `!cancelled()` on the P3 step deletes the legacy step's failure artifacts

`.github/workflows/e2e-smoke.yml:97,106` and `:108-116`. Playwright clears `outputDir` at the start of every run (`removeFolders([outputDir])`, `node_modules/playwright/lib/common/index.js:3147`); both steps use the default `test-results/`, and `trace`/`screenshot`/`video` are `retain-on-failure`. When the legacy step fails, the P3 step now runs anyway (that is the point of `!cancelled()`), wipes `test-results/`, and the upload step at the end ships only the P3 run's folder. Before this PR the create-kinds step had no `!cancelled()`, so a legacy failure kept its traces.

Failing scenario: `organiser-home.spec.ts` fails in the legacy step on a PR; the P3 step runs 5 minutes and passes; `playwright-test-results` contains no trace, screenshot or video for the failing test. Fix: give the P3 script its own output folder (`playwright test ... --output test-results-p3`) and add `test-results-p3/` to the upload `path`, or upload after each step with distinct artifact names.

### F6. Nits

- `scripts/check-p3-specs-not-skipped.mjs:70-74` (`scriptSpecs`): a non-spec token after `playwright test` (a directory `tests/e2e/p3/`, a glob, `--grep-invert p`) is silently dropped. A directory would exit 2 only if it emptied the P3 count; with other P3 specs present its contents are simply unchecked, and `--grep-invert` filters tests out of a listed spec with exit 0. CLAUDE.md says the list is explicit, so this is a nit: refuse any positional token that is not a `.spec.*` file (exit 2) and any `--grep*` flag in a gate script.
- `.github/workflows/e2e-smoke.yml`: the blob went CRLF -> LF. `.gitattributes` says `* text=auto eol=crlf`, so LF in the repo is the normalised form and checkouts still get CRLF; harmless, just noting the whole-file byte diff is renormalisation, not content (content diff is +15/-6).
- Handover `docs/handover/guard-p3-walk-specs.md` still says "27 cases" in one place and "22 cases" in another; the script has 27.
- `pre-ship` runs `test:e2e` only (acknowledged in the PR). Until it also runs `test:e2e:p3`, the local ship gate proves nothing about the eight P3 specs; the first local signal is CI.

## The brief's six questions

1. **Guard fail-open.** Tried 20 constructions (`/tmp` harness feeding `runCheck` fixtures). Fail-closed (exit 1 or 2): skip in `beforeEach`, describe-level callback skip, `let` instead of `const` for the flag, `!== 'TRUE'`, template-literal key, ternary on the flag, flag as `${{ vars.X }}`, flag set only in `playwright.config.ts` `webServer.env`, flag `'false'`, unconditional `test.skip()`, a spec moved back into `test:e2e`, a directory token (exit 2). Mutation: 12/16 red, survivors in F5.
2. **e2e-smoke.yml.** New step has `!cancelled() && docs_only != 'true'`; legacy step env unchanged (same four keys, byte-identical). The flags are on the step, and `webServer.env` in `playwright.config.ts` merges with `process.env`, so the dev server sees them (the 86-passed CI run is the proof). Side effect: F4.

Correct in both schemes.
