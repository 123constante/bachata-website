Reviewed head: `7a64720bb` (branch `claude/ci-e2e-scope`). This is a read-only review; nothing was pushed to the PR branch.

## Verdict
Do not merge yet. `emit()` was never changed to write `e2e_skip`, so the step output is always empty and the suite always runs. That is safe, but it means the PR does nothing.

## Hard-tier: FAIL
Reviewed head SHA: 7a64720bb

## Findings
- **BLOCKER:** `scripts/ci/docs-only.mjs`: `emit(result, e2eSkip)` calls the old one-parameter `emit(v)`, which writes only `docs_only=...`. The second argument is dropped and `e2e_skip` never reaches stdout or `$GITHUB_OUTPUT`. I ran it with GITHUB_OUTPUT set and piped in `supabase/a.sql`; the only output was `docs_only=false`. Because `'' != 'true'`, every step in e2e-smoke.yml still runs on every PR. Fix: emit both lines, and add a self-test or vitest case that checks the emitted output, not just the `isE2eSkippable()` return value. The current self-test is green (`56 cases, 20 mutants, ok`) and does not catch this.
- **Check 1 (YAML/CRLF/consumers):** PASS. The YAML parses. The blobs stay LF on both main and the PR, and `.gitattributes` `eol=crlf` converts on checkout, so line endings are unchanged. No step in e2e-smoke.yml still reads `docs_only`. unit-tests.yml, workflow-lint.yml and the other `docs_only` readers are unaffected because the `docs_only=` line is unchanged.
- **Check 2 (fail-safe):** PASS by construction. `e2eSkip` defaults to false; a throw, an empty diff (`[]` gives false) or a non-PR event leaves it false; unknown paths give false. The extra sanity guard in `isE2eSkippable` (`classify(p, vetoAll-only) === false`) is always true when it runs, so it adds nothing. The explicit `..`, `/`, `""` and `"` checks do the real work and are stricter than RULES (`includes('..')`). Not harmful, but the dead clause makes it harder to read.
- **Check 3 (skip list):** PASS for the paths the brief lists. I tested `isE2eSkippable` directly: src/, public/, package.json, package-lock.json, playwright.config.ts, vite.config.ts, tests/e2e/, scripts/ and `.github/workflows/e2e-smoke.yml` all give false. A PR that edits e2e-smoke.yml still runs the suite.
- **LATENT RISK:** `E2E_BLIND` includes all of `.github/`, not just `.github/workflows/`. `.github/actions/x/action.yml` gives true. There are no local composite actions today, and e2e-smoke.yml has no `uses: ./...`. If one is added later and e2e-smoke uses it, an edit to it would skip the suite that runs it. Suggest narrowing to `.github/workflows/` (plus any `.github/` files known to be inert), or vetoing `.github/actions/`.
- **NIT:** `E2E_OWN` lists `.github/workflows/typecheck.yml` with no comment explaining why. This makes the skip more conservative, so it is not unsafe, but the reason should be written down. No E2E case covers it.
- **NIT:** `.claude/hooks/*` and `supabase/functions/*` are skippable. That is correct for this suite, because the smoke specs route-mock all Supabase traffic, and the real-Supabase specs in tests/e2e are not in `test:e2e` / `test:e2e:p3`. Still, it is worth stating in the comment that the real-RPC configs are outside this gate.
- **Check 4 (push / workflow_dispatch):** PASS. Any event other than `pull_request` (or unset) skips the diff and leaves both outputs false, so every step runs.
- **Check 5 (tests):** `node scripts/ci/docs-only.mjs --self-test` passes (56 cases, 20 mutants). The new E2E_CASES are not part of the mutation loop, and no unit test covers `emit` (see BLOCKER). I found no vitest file for docs-only.mjs.
