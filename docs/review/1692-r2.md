## Findings

1. **Nit: the snapshot-before-suite wiring is unpinned.** `scripts/unit-stamp.mjs:21`. The mutant `canWriteStamp(now, now)` throws `before` away and still passes all 11 tests. Only the pure `canWriteStamp` is tested, not `writeStamp(before)`. A regression would bring back the r1 race unnoticed. Fix: in the temp-repo test, call `snapshotTree()`, change the tree, call `writeStamp(before)`, and assert false and no file.
2. **Nit: `writeStamp()` with no argument falls back to `before = now`.** `scripts/unit-stamp.mjs:21` (`before || now`). Nothing reaches this today: pre-ship guards on `unitBefore` and the CLI does not export a write path. But the export stamps a clean tree with no pre-suite snapshot and no proof a suite ran. Making it fail closed is cheap: `if (!before) return false;`.
3. **Nit (residual, accepted): a tree edited mid-suite and reverted before the suite ends is still stamped.** This is inherent to snapshotting HEAD^{tree} and clean status. The window is narrow, and CI's full suite is the merge backstop.
4. **Nit: the hook message says "pre-ship passed".** `.githooks/pre-push:147`. The stamp is written when `test:unit` is green, even if a later pre-ship check fails. Accurate wording: "test:unit passed in pre-ship on this exact tree". This is cosmetic, and the gate it replaces is unit-only.
