## Findings

### F1 (BLOCK) F-33: event-page invalidation misses every bridged series

`src/modules/organiser/shared/publicCache.ts:21-23`

```ts
predicate: (q) => q.queryKey[0] === EVENT_PAGE_QUERY_ROOT && q.queryKey[1] === seriesId,
```

`seriesId` is `ws.series.id` (`event_series_p5.id`, from `admin_event_workspace_p5`). The public page's key is `eventPageQueryKey(validId, occ)` (`src/modules/event-page/useEventPageQuery.ts:357`), and `validId` comes from `useEntitySlugOrId(param, 'events')` (`src/pages/EventPage.tsx:46-47`), which calls `resolve_public_event_ref_v1` and returns `id = COALESCE(legacy_event_id, id)` (`src/lib/seo/useEntitySlugOrId.ts:53-62`; function body read on prod 2026-10-31: `jsonb_build_object('id', COALESCE(r.legacy_event_id, r.id), ...)`).

Prod shapes (read-only, counts, `event_series_p5`):

| lifecycle | legacy_event_id set and differs from id | no legacy id |
|---|---|---|
| live | 59 | 10 |
| ended | 21 | 0 |
| paused | 1 | 1 |

So for 81 of 92 public series the predicate is false and the event page keeps the hour-old data: the row's exact symptom, on the majority shape. The calendar half is fine (root-prefix invalidation).

Why the tests are green: `publicCache.test.tsx:27-29` seeds `eventPageQueryKey(S, null)` with the same `S` the helper is called with. No row seeds the key with a different public id. The builder's handover line "the page key's second part is the series UUID" is the wrong id.

The workspace does not carry the legacy id (`admin_event_workspace_p5` and `_snapshot_series_p5` bodies never mention `legacy_event_id`; `eventModel.ts` has no such field), so the helper cannot match it today.

Fix (smallest, no DB change): invalidate the event-page root like the calendar root.

```ts
export function invalidatePublicEventCaches(qc: QueryClient): void {
  void qc.invalidateQueries({ queryKey: [EVENT_PAGE_QUERY_ROOT] });
  void qc.invalidateQueries({ queryKey: [CALENDAR_EVENTS_QUERY_ROOT] });
}
```

Keep the `seriesId` parameter only if you want it for a later narrowing. Add a comment with the reason: the public key is `COALESCE(legacy_event_id, id)` and the workspace has no legacy id. An organiser's tab holds few event pages, so the cost is one refetch per open page. In the test, flip `STALE.pageOther` to `true` and add a row `pageLegacy: eventPageQueryKey('legacy-9', null)` expected stale, with the reason in a comment, so the next person who narrows it by id has to meet this row. Alternative (heavier): expose `legacy_event_id` in `admin_event_workspace_p5` from the admin repo and match both ids.

### F5 (low) F-34: the paused copy says dancers cannot see it; the server serves the page

`src/modules/organiser/p3/data/eventPage.ts:382` `paused: 'It is hidden now. Show it again and dancers can see it.'`

Prod, read-only: `event_view_p5` serves `live`, `paused`, `ended` to `anon`; `_p5_paused_hides_occurrence_v1` (owner decision 2026-10-08, quoted in its body) says "a PAUSED series keeps its public page and its PAST dates". `resolve_public_event_ref_v1` resolves a paused series when it has a past public date. So a dancer with the link sees the page of a hidden event (past dates only, no notice). The builder's reading ("Hidden" so no link) matches the existing owner copy (`eventPage.ts:209,281`), but not the server. The purpose of the row is to see what dancers see, and dancers can see it.

Recommended: open the link for `paused` too, subline "Hidden from the calendar. The page still opens with past dates only." If the lead keeps it off, change the reason to "Hidden from the calendar. Anyone with the link still sees past dates." Either way the shape row `paused` in `dancerView.matrix.test.tsx:41` changes. The pre-existing owner copy at `:209,281` has the same inaccuracy and is out of this PR.

### F6 (nit) F-34: slug-null fallback 404s for a bridged series

`eventPage.ts:388` passes `event_id: ws.series.id`. `eventHref` falls back to `/event/<P5 id>` when slug is null (`src/lib/seo/eventHref.ts:13`). `resolve_public_event_ref_v1` on the UUID branch matches `legacy_event_id = uuid OR (legacy_event_id IS NULL AND id = uuid)`, so a bridged series' P5 id is not found. Prod: every live, ended and paused series has a slug (69, 21, 2), so unreachable today; the test `falls back to the id when a live series has no slug` (`dancerView.matrix.test.tsx:84-87`) pins a path that would 404 for 81 of 92 series. Fix: when `slug` is null return `{ href: null, why: 'The page has no address yet.' }` (or similar), and change that test to expect the off row.
