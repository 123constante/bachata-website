## Findings, ranked

**R2 (should-fix, CONFIRMED, money copy). A late outcome never says WHICH order or ticket it is about, so r1 F2's wrong message still lands at the wrong moment.**
`RefundSheet.tsx:50` `onLate('Refund started.', true)`; `TypeSheet.tsx:112-116,130` pass the same texts late as in-sheet. `TicketsEntry.tsx:129-132` shows them verbatim. The F2 test itself shows the result: B's Refund sheet is open and a toast "Refund started." appears over it (`stack.draft.test.tsx:262-264` asserts only that the toast exists and B's layer survives). Scenario (r1 F2's, after fix 1): Refund A, confirm, Keep the order, tap Refund on B; A lands: over B's "Refund this order?" sheet a toast says "Refund started." The sheet no longer vanishes, but the words still read as B's. The late refusal is worse: "That did not work. Try again in a moment." names nothing, and A's Refund button is back by then (`onSettled` at `:48` runs before `onLate`).
Fix: name the subject in the late text only, e.g. `onLate(\`Refund started for ${buyerNameOf(order)}'s order.\`, true)` / `\`Ticket "${form.name.trim()}" saved.\``; keep the in-sheet words as they are. Pin it in the F1 / F2 tests (`toast.textContent` contains the name).

**R1 (should-fix, CONFIRMED by P1 / P1b, money a11y). The late-refusal alert is one slot: any later toast replaces it.**
`TicketsEntry.tsx:94` holds ONE `toast`; `say()` (`:95`) and `late()` (`:130`) both overwrite it; `:357` renders one `TicketToast`. Scenario: Refund A, confirm, Keep the order, flip a Selling switch while waiting; A is refused ("Payments are not switched on yet...", `role="alert"`, no timer); the switch lands: `say("Standard: Selling")` replaces the alert with a polite status that is gone in 8 s. The person never learns A's refund did not happen; A's row simply shows Refund again. Two late refusals (A then B) show one unlabelled line (P1b). A late success "Refund started." arriving after a late refusal does the same.
Fix: keep the alert separate from the status (`alert` state + `status` state, two elements), or a small queue for alerts; a status never clears an alert. Then the F3 test can assert that a `say()` after the alert leaves it on screen.

**R3 (should-fix, CONFIRMED by mutation M3, CI-guard class). The F3 test's "stays until dismissed" half is not a gate.**
`stack.draft.test.tsx:296-306`: the toast mounts under REAL timers (the 8 s `setTimeout` is scheduled in `TicketToast`'s effect at mount), then `vi.useFakeTimers()` is installed and `advanceTimersByTime(60_000)` advances only the fake clock. With `if (alert) return;` removed (M3) the real timer is still pending when the assertion runs, so the test passes against the mutant it exists to catch. Per CLAUDE.md's mutation rule this is the "gate stays green against the mutant" case: the product code at `:364` is right, the test is not.
Fix: `vi.useFakeTimers()` BEFORE `show(...)`, `act(() => vi.advanceTimersByTime(8_001))`, assert the alert is still there; in the same test (or a twin) assert a status toast IS gone at 8 s, so the timer path is proven too.

**R4 (should-fix, CONFIRMED by P6). r1 F4 is half-fixed: a save success still clears every row's switch reason.**
`TicketsEntry.tsx:335` `onSaved` does `setMoveError(new Map())`; the switch path was fixed at `:153` (`with_(m, null)`), the save path was not. Scenario: switch on paid type A refused ("Connect payments in You > Get paid..."), edit free type B, Save changes: A's reason disappears while A is still Not on sale, with nothing under it. Same for "Close sales for good" (`TypeSheet.tsx:130` goes through `onSaved`).
Fix: in `onSaved`, delete only the saved type's id (`editing.type?.id`), or leave the map alone; add P6 as a test.

**R5 (nit, CONFIRMED by P9). Escape during an in-flight "Close sales" hides the Closing indicator.**
`TypeSheet.tsx:203` `onEscape={confirmClose ? ... : undefined}` has no `busy` guard. After "Close sales" is tapped (`saving === 'close'`, button says "Closing..."), Escape swaps the confirm block for "Close sales for good" (`:318`) as if nothing were running. No second send: the confirm button is `disabled={busy}` (`:312`) and the landing goes through `landed` either way. Fix: `onEscape={confirmClose && !busy ? ... : undefined}` (Escape then closes the layer, which is the designed mid-flight behaviour), or keep the confirm block while `saving === 'close'`.

**R6 (nit, a11y). The alert's Dismiss sits outside the open dialog.**
`TicketsEntry.tsx:357` renders the toast after the sheets, outside every `aria-modal="true"` dialog (`StackSheet.tsx:115`). Screen readers that honour `aria-modal` confine browse mode to the dialog: the alert is announced (live region), but its Dismiss cannot be reached until the sheet closes. Tab reaches it (no focus trap in `StackSheet`), so keyboard users are fine. Acceptable if documented; otherwise render the toast inside the top layer's sheet.

**R7 (nit, a11y). A status toast that turns into an alert is the same DOM node.**
`TicketsEntry.tsx:369`: the `div` is reused, only `role` and the text change. Several screen readers do not re-announce a role change on a live node. Fix: `<TicketToast key={toast.alert ? 'alert' : 'status'} ...>` so the alert is a fresh node.

**R8 (nit, test scope). `layout.cascade.test.ts` ignores `!important` and longhands (M8, M9 green).**
Real cascade check for shorthand-vs-shorthand conflicts of plain class / tag rules; a `padding-top` or an `!important` re-pad would pass it. Say so in its header comment, or add a one-line assertion that `p3.css` contains no `!important` (it does not today) and that no rule sets `padding-top` on `.p3-date-btn`.

**R9 (nit, pre-existing window, server-guarded). Between `onSettled` and the refetch, a refunded order's Refund button is enabled on stale status.**
`RefundSheet.tsx:48` unlocks the row before the answer is shown; `late` refreshes after (`TicketsEntry.tsx:131`). For the refetch's latency the person can open A's Refund sheet again and confirm; the edge function refuses an order already refunding. Not fix-1's change (round 2), noted for the owner walk.
