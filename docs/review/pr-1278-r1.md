## Findings (most severe first)

### F1 (fix before merge, CONFIRMED): the paused toast says "paused" and "dancers do not see it"; P3 says "Hidden", and the public page can still show it
- `src/modules/organiser/p3/model/saveWords.ts:60-68`: `'Saved. It is paused, so dancers do not see it.'` and the six sibling lines.
- Vocabulary: P3 renamed Pause to Hide (C3 B3). `p3/model/labels.ts:57` tag `Hidden`, `:65` control `Hide from the calendar`; `p3/model/status.ts:33` maps `paused` to key `hidden`. The organiser never meets the word "paused" anywhere else on a P3 screen, so the toast names a state the screen does not show.
- Truth: a paused series WITH a past public date resolves on `/event/:id` for anon (200, indexable, in the sitemap) under the "On hiatus" banner: `src/modules/event-page/bento/EventPausedBanner.tsx:1-6` (comment, admin #716/#718), `src/lib/seo/eventPageSeoPolicy.ts:12-21`, `src/modules/event-page/festivalEventQuery.ts:34-36` (the gate is `lifecycle_status IN ('live','paused','ended')`), and the test `buildEventPageModel.paused.test.ts:107` "paused does not mark the page unavailable (page stays reachable for anon)". The details and prices the organiser just saved render on that page. What is true is "hidden from the calendar", which is exactly the P3 control's words.
- Concrete failing input: either of prod's 2 paused series (counts below) with a past date. Organiser edits the description on Details, taps Save, reads "Saved. It is paused, so dancers do not see it." A dancer who has the link opens the page and reads the new description under "On hiatus".
- Suggested words (keep one lead-in, as the PR does): `Saved. It is hidden from the calendar.` / `Saved for all dates. It is hidden from the calendar. A date with its own pictures keeps them.` / `Prices saved. The event is hidden from the calendar.` / `Saved for every date. It is hidden from the calendar.` etc. Update the matrix regex at `saveWords.matrix.test.ts:52` and the header comment at `saveWords.ts:9`. Blast radius is 2 series, so this is fix-before-merge, not a blocker.
