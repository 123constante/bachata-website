## Findings

**F1 (BLOCKER): raw Unicode punctuation in `VenueList.tsx` reds the module unit suite.**
`src/modules/organiser/p3/screens/VenueList.tsx:6` (`…`) and `:7` (`’`). `npx vitest run src/modules/organiser`
on the branch gives 1 failed / 8420 passed. The failure is
`consistency.matrix.test.tsx > G3 > no non-test source in the module has raw Unicode punctuation outside comments (B-N8)`.
The same test passes on main (58/58). This also breaks the CLAUDE.md HTML-entities rule.
*Fix:* `'Loading the places…'` and `'We couldn’t load the places. ...'`. Better still, see F5: reuse the
existing `L.detailsPlaceFail` (`labels.ts:240`, already `’`) instead of new strings.

**F2 (medium): F-24 has no test.** Neither new test file covers the router blocker, and the builder's
red-first gap applies here in full. The probe I ran is below; commit it as a new file
(for example `__tests__/dateFieldLeave.test.tsx`). It mounts `DateFieldSheet step="edit-name"` in a
`createMemoryRouter` with routes `/a`, `/b` (the sheet) and `/c`. It has four cases:
(1) clean: `router.navigate('/c')` lands, so it never blocks;
(2) dirty: navigating to `/c` stays on `/b` and shows `p3-field-ask`, Stay keeps the typed value, and Leave lands on `/c`;
(3) dirty: `router.navigate(-1)` stays and asks;
(4) dirty: Escape does not call `onClose` and asks.
Results: 4/4 green on the branch; cases 2 and 3 red on main's `DateFieldSheets.tsx`. Extend it with `it.each` over
`edit-name | edit-photos | edit-price` so it is table-driven over the three sheets the row names.

**F3 (low): the F-17 tests stay green on unfixed code.** `editorStates.test.tsx` tests `VenueList`
on its own. With main's `DetailsScreen.tsx` and `DateSheet.tsx` restored (still the dead sheets), all
four F-17 tests pass. Nothing proves either sheet uses the shared piece. *Fix:* add a table over
`[Details place sheet, date Where sheet] x [failed, empty]`. Render each screen with `useVenueOptions`
mocked and assert `p3-venues-retry` plus the empty or fail line inside the open sheet.

**F4 (low): the F-18 test is a label unit test, not a screen x shape test.** It goes red on main only
because `L.pricesNone` changed from a string to a function, not because of anything the person sees.
Neither file renders `PricesScreen` with a festival that has 0 prices. *Fix:* add `PricesScreen` x
`[festival 0 prices, weekly 0 prices]`. Assert that `p3-free-switch` is absent or present and that `p3-prices-empty`
mentions "free" only when the switch renders.

**F5 (low, owner rule 1: one mapping): copy now exists twice.**
(a) `VENUE_LIST_COPY.fail` duplicates `L.detailsPlaceFail` (`labels.ts:240`) and `DATE_COPY.noVenues` (`dates.ts:246`).
Both of those are now dead, with no importer. *Fix:* delete them, or point `VENUE_LIST_COPY` at one of them.
(b) The Removed StateCard body (`EventPage.tsx:300-302`, hard-coded title and text) restates
`STATUS_COPY.archivedWhy` (`eventPage.ts:223`) in different words. *Fix:* use `STATUS_COPY.archivedWhy`, or move both into
one constant.
(c) `EventPage.tsx:301` hard-codes `p3-tag-removed`. *Fix:* use `` `p3-tag p3-tag-${removedStatus().key}` `` so the class
comes from the same mapping as the label.

**F6 (low): the archived Details lock test was deleted with no replacement.** `editScreens.send.test.tsx:218`
dropped the `archived` case. `removedEvent.test.tsx` covers EventPage and Prices but not Details,
AllDates or History. *Fix:* extend the `it.each` in `removedEvent.test.tsx` to all five gated screens.
That is the deep-link shape on every screen it can land on. Product note for the lead: History of a
removed event is no longer viewable. That fits the brief, but it is a behaviour change.

**F7 (nit): the VenueList empty copy says "ask the team to add your place"** but offers no way to ask.
Other P3 copy says "ask the Bachata Calendar team", with the same lack of a control, so this is consistent and not a
blocker. Consider aligning the wording ("ask the Bachata Calendar team").

**F8 (nit): `useLeave` gets a fresh inline `setAsk` every render** (`DateFieldSheets.tsx:47`). So
`useRegisterLeaveAsk` re-registers on every render, and the blocked-state effect re-runs. That is harmless (the
`setAsk('route')` bails out on the same value), but a `useCallback` would match EditTray's use.
